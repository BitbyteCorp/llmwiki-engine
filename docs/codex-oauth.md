# Codex OAuth
엔진은 자체 ChatGPT 로그인을 SQLite에 보관하고 Codex 응답 모델 호출에 사용하며, 사용자 웹 로그인과 임베딩 인증은 별도로 유지한다.

## 배경

ChatGPT 계정으로 도니의 응답 모델을 사용하려면 엔진이 액세스 토큰과 리프레시 토큰의 수명 주기를 소유해야 한다. 개발자 PC의 `~/.codex/auth.json`을 읽거나 복사해 공유하지 않는다. Codex CLI와 엔진이 같은 리프레시 토큰을 사용하면 한쪽의 토큰 회전으로 다른 쪽의 갱신이 실패할 수 있기 때문이다. 엔진 전용 로그인으로 얻은 자격 증명은 엔진 데이터와 함께 관리한다.

이 로그인은 OpenAI가 인가 서버이고 엔진이 클라이언트인 모델 접근 인증이다. [인증](auth.md)의 Google 웹 로그인과 엔진이 인가 서버가 되는 MCP OAuth는 사용자와 지식 저장소 접근을 위한 별도 흐름이며, Codex 로그인으로 웹 사용자나 MCP 접근 토큰을 만들지 않는다.

## 내용

### 명령과 로컬 로그인

엔진과 같은 환경변수·SQLite 데이터 경로를 사용하는 실행 환경에서 다음 명령을 실행한다.

```bash
pnpm cli codex login
pnpm cli codex status
pnpm cli codex logout
```

| 명령 | 동작과 공개 정보 |
| --- | --- |
| `codex login` | 브라우저에서 열 인가 URL을 출력하고 로컬 콜백 또는 표준 입력 붙여넣기를 최대 10분간 기다린다. 성공하면 엔진 자격 증명을 저장한다. |
| `codex status` | 로그인 여부와 저장된 이메일·ChatGPT 계정 ID·액세스 토큰 만료 시각만 JSON으로 출력한다. 토큰 원문은 출력하지 않으며 상태 조회만으로 갱신하지 않는다. |
| `codex logout` | 엔진 SQLite의 자격 증명을 제거한다. 별도 Codex CLI 로그인이나 엔진 웹 세션을 지우거나 OpenAI 계정 전체 세션을 폐기하는 명령이 아니다. |

`login`은 PKCE S256과 임의의 `state`를 사용하는 인가 URL을 출력하며, 콜백 수신 서버는 `127.0.0.1:1455`에만 바인딩한다. OpenAI에 등록된 리디렉션 URI는 **`http://localhost:1455/auth/callback`로 고정**되어 있다. `PUBLIC_URL`이나 엔진의 웹 도메인·웹 포트로 바꾸지 않는다. 공개 웹 서버에 콜백을 노출하거나 역방향 프록시 경로를 추가할 필요가 없다.

출력된 URL을 브라우저에서 열고 ChatGPT 계정으로 로그인한다. 브라우저 콜백을 받으면 터미널의 성공 안내와 브라우저의 완료 페이지를 확인한다. 현재 로그인 시도의 `state`를 검증한 첫 번째 유효한 콜백만 인가 코드를 교환하고 저장하며, 브라우저와 붙여넣기가 동시에 완료되어도 코드를 두 번 교환하지 않는다. 잘못된 `state`는 안전한 400 응답으로 거절하고 원래 로그인은 계속 기다린다.

터미널에서 `Ctrl-C` 또는 프로세스의 `SIGINT`·`SIGTERM`으로 취소할 수 있다. 성공·교환 실패·입력 오류·10분 만료·취소 시 임시 서버와 입력 인터페이스를 정리한다. 취소 이후 늦게 끝난 코드 교환 결과는 저장하지 않는다. 콜백 URL·인가 코드·토큰은 로그나 명령행 인자로 전달하지 않는다. 붙여넣기 입력은 TTY에서도 화면에 표시하지 않는다.

### 원격 서버와 컨테이너

브라우저의 `localhost`는 엔진 서버가 아니라 브라우저를 실행하는 PC를 뜻한다. SSH·컨테이너 환경에서는 다음 두 방법 중 하나를 사용한다.

1. **붙여넣기**: 원격 엔진에서 `pnpm cli codex login`을 실행하고 출력된 인가 URL을 로컬 브라우저에서 연다. 브라우저가 최종 `localhost:1455` 페이지에 연결하지 못하더라도 주소창의 **전체 리디렉션 URL**을 복사해 기다리는 엔진 터미널에 붙여넣는다. `code#state` 형식도 지원하며 두 값 모두 같은 로그인 시도의 것이어야 한다. `code`만 붙여넣으면 수용하지 않는다.
2. **SSH 포워딩**: 로컬 PC에서 다음 터널을 연 뒤 원격 엔진에서 로그인한다. 로컬 PC의 1455 포트와 원격 엔진의 1455 포트가 비어 있어야 한다.

   ```bash
   ssh -L 1455:localhost:1455 user@engine-host
   # 연결된 원격 셸에서 실행한다.
   pnpm cli codex login
   ```

컨테이너는 실제 로그인 프로세스가 실행되는 네트워크 공간의 루프백에 바인딩하므로 호스트로의 SSH 포워딩만으로 컨테이너 내부 루프백에 연결되지는 않는다. 이 경우 같은 데이터 볼륨·설정을 사용하는 컨테이너 터미널에서 로그인하고 붙여넣기 방식을 사용한다. `PUBLIC_URL` 변경으로 해결하지 않는다.

1455 포트가 이미 사용 중이면 CLI는 바인딩 실패와 붙여넣기·포워딩 안내를 출력하고 붙여넣기를 계속 기다린다. 브라우저 콜백을 받으려면 충돌하는 프로세스를 먼저 정리하고 다시 로그인해야 한다. 붙여넣기는 임시 콜백 서버나 브라우저의 해당 서버 연결 성공에 의존하지 않는다. 리디렉션 URL과 `code#state`는 일회용 비밀 입력이므로 셸 명령·공유 채팅·로그에 남기지 않는다.

### 저장과 갱신

`codex_credentials` 테이블은 `id=1`인 단일 엔진 계정 행을 보관한다. 다시 로그인하면 이 계정을 교체하며, 웹 사용자별 자격 증명을 저장하지 않는다.

| 저장 항목 | 의미와 보호 경계 |
| --- | --- |
| `access_token` | Codex 응답 모델 요청에 사용하는 액세스 토큰이다. |
| `refresh_token` | 만료 임박 시 새 토큰을 얻는 비밀 값이며, 회전된 값으로 교체한다. |
| `id_token` | 발급된 경우 계정 메타데이터와 함께 보관하는 ID 토큰이다. |
| `account_id`, `email` | ChatGPT 계정 식별자와 발급된 경우의 이메일이다. |
| `expires_at`, `updated_at` | 액세스 토큰 만료 시각과 마지막 저장 시각을 ISO 형식으로 기록한다. |

토큰 원문은 엔진 SQLite에 저장하므로 데이터 디렉터리·볼륨·백업을 자격 증명으로 취급하고 파일 접근을 제한한다. DB를 공유하거나 문서·오류 출력에 토큰을 복사하지 않는다. `status`는 토큰을 공개하지 않는 운영 확인 경로다.

모델 호출 시 액세스 토큰의 남은 유효 기간이 **5분 이하**이면 먼저 갱신한다. 이는 5분마다 실행하는 주기 작업이 아니라 자격 증명을 요청할 때 적용하는 만료 여유다. 같은 엔진 서비스의 동시 갱신 요청은 하나의 진행 중 갱신을 공유하고 새 자격 증명을 저장한다. 별도 Codex CLI의 토큰 파일과 동기화하지 않는다. 갱신이 거절되면 엔진 실행 환경에서 `pnpm cli codex login`으로 다시 로그인한다.

### 모델과 임베딩의 경계

`LLM_PROVIDER=openai-codex`는 도니의 응답 모델을 ChatGPT Codex 경로로 선택한다. 구체적인 모델 선택과 제공자 동작은 [도니](agent.md)를 따른다. Codex 로그인은 OpenAI Embeddings API의 API 키를 대신하지 않는다. 임베딩에는 별도의 `OPENAI_API_KEY`가 필요하며, ChatGPT 구독과 API 사용 권한·요금은 구분해서 관리한다. Codex만 로그인하고 임베딩 키를 생략한 구성을 완전한 검색 설정으로 간주하지 않는다.
