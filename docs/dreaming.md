# dreaming

dreaming은 매일 변경된 지식을 검토·정리하고 일기를 남기는 배치 작업이다.

## 배경

개별 쓰기 요청을 반영하는 것만으로는 기존 지식과의 충돌이나 중복을 함께 정리하기 어렵다. dreaming은 변경된 노트와 관련된 기존 노트를 함께 검토해 누적된 지식을 정돈한다. 예를 들어 새 노트가 기존 노트와 같은 내용을 다루면 두 노트를 검토해 중복을 정리한다.

지식 저장소의 파일 배치, 일기의 경로, 메모리 파일의 역할과 GitHub 백업 정책은 [지식 저장소](knowledge-repository.md)에 설명한다.

## 내용

### 실행 시각과 입력

매일 03:00 `Asia/Seoul`에 실행한다. 입력은 직전 dreaming 이후 main에 들어온 커밋이다. 따라서 검토 범위는 단순히 현재 파일 전체나 날짜가 같은 커밋이 아니라 이전 실행 이후 반영된 변경이다.

[웹 대화 기록](web.md#대화-기록과-학습)도 입력에 포함한다.

### 정리 작업

main에서 작업 워크트리를 파생하고 Luna가 다음 작업을 수행한다.

- 변경된 노트와 의미적으로 가까운 기존 노트를 찾아 지식의 충돌과 중복을 정리한다. 유사 노트 조회에는 [RAG](rag.md)를 사용한다.
- 깨진 위키링크와 `index.md`를 정리한다.
- 메모리 파일인 `MEMORY.md`에서 낡은 항목을 정리한다.
- 그날의 일기를 작성한다.

편집에는 [작성 규칙](writing-rules.md)을 적용한다. 작업 결과는 커밋한 뒤 main에 머지하며, 충돌이 발생하면 Luna가 해결한다. 작업 워크트리 격리, 직렬 머지와 머지 후 처리 방식은 [쓰기 흐름](write-flow.md)을 따른다.

### 백업과 실패의 관계

dreaming 후 GitHub에 main을 하루 한 번 push한다. dreaming이 실패하더라도 main push는 시도한다. GitHub는 백업이므로, 정리 작업의 실패가 이미 main에 반영된 지식의 백업까지 막아서는 안 되기 때문이다.
