# 라이브 미리보기 편집기
Markdown 원문 하나를 CodeMirror 6의 장식과 위젯으로 표시하고, 같은 문서에서 바로 편집한다.

## 배경
읽기 화면과 원문 편집기를 오가면 작성 중인 위치를 잃고 미리보기와 원문을 별도로 관리하게 된다. 편집 가능한 현재 노트는 라이브 미리보기를 기본으로 사용한다. 조회자, 다른 그룹이 편집을 소유한 노트, 과거 버전은 기존 Markdown 읽기 렌더러를 유지한다. 자동 저장과 원문 전환 메뉴의 작업 공간 흐름은 [웹](web.md)에 설명한다.

## 내용

### 원문과 표시의 경계
문서의 진실 원천은 CodeMirror 문서의 Markdown 문자열이다. 장식은 문자를 가리거나 글꼴을 바꾸며 위젯은 해당 범위의 표시만 대체한다. 렌더링, 초점 이동, 라이브 미리보기와 원문 전환은 문서를 고치지 않는다. 할 일 체크박스를 누르면 해당 `[ ]` 또는 `[x]`의 가운데 문자 하나만 바꾼다. 기존 위키 링크 자동완성과 이미지 붙이기·끌어 놓기는 사용자의 입력으로 문서를 변경한다.

편집기의 `variant`는 하나의 CodeMirror `Compartment`를 재설정한다. `live`는 읽기 화면과 같은 비례 글꼴과 최대 너비를 사용하며 gutter와 활성 줄 배경을 표시하지 않는다. `source`는 monospace, 줄 번호, 접기 gutter, 구문 강조와 frontmatter 원문을 표시한다. 두 형태 모두 내부 스크롤 영역을 만들지 않고 상위 노트 본문이 스크롤을 소유한다. 저장이나 이미지 업로드 중에도 입력을 막지 않으며 `readOnly`만 편집을 비활성화한다.

### 구문 드러내기
편집기에 초점이 없으면 모든 지원 구문을 렌더링한다. 초점이 있을 때 선택 영역이 인라인 구문 안이나 경계에 닿으면 그 구문의 원문을 드러낸다. 제목, 목록 표식, 인용과 블록은 선택 영역이 해당 줄이나 블록의 줄에 닿으면 원문을 드러낸다. 여러 선택 영역도 같은 규칙을 적용한다. 가린 범위는 atomic 범위로 등록하여 커서 이동 중 보이지 않는 표식 안에 멈추지 않게 한다.

표·수식·Mermaid·callout에는 `원문 편집` 버튼을 둔다. 버튼이나 링크·접기 조작을 제외한 블록 내용을 누르면 해당 블록 안에 커서를 놓고 초점을 옮겨 원문을 드러낸다. 속성 위젯은 저장된 frontmatter를 처음부터 펼쳐 표시하며, 속성의 일반 영역이나 편집 버튼을 누르면 YAML 안에 커서를 놓는다. 태그 링크는 기존 태그 이동 동작을 유지한다.

### 구문별 표시
| 구문 | 라이브 표시 |
| --- | --- |
| ATX·setext 제목 | 표식을 가리고 h1–h6 크기를 적용한다. |
| 강조·굵게·취소선·인라인 코드 | 구분 표식을 가리고 글꼴과 배경을 적용한다. |
| `[문구](주소)` | 주소를 가리고 문구를 링크로 표시하며 문구 안의 인라인 Markdown도 렌더링한다. |
| `[[대상#제목\|별칭]]` | 기존 이름 해석 조회를 사용하며 해결됨·확인 중·없음·여러 후보 상태를 구분한다. |
| 이미지 | 읽기 렌더러와 공유하는 `imageSource` 정책을 적용한다. HTTPS와 노트 기준 상대 assets 경로만 표시하고 허용되지 않는 경로는 대체 문구를 표시한다. |
| 글머리·할 일 목록 | 글머리를 `•`로, 할 일 표식을 조작 가능한 체크박스로 표시한다. |
| 인용·callout | 인용 표식을 가리고 왼쪽 선을 표시한다. Callout은 기존 종류·기본 제목과 `-`·`+` 접기 동작을 그대로 사용한다. |
| 수평선 | 구분 표식을 선으로 표시한다. |
| fenced 코드 | 배경, 코드 언어 강조, 언어 이름과 복사 버튼을 표시한다. 편집 위치가 블록 안이면 fence도 드러낸다. |
| GFM 표·Mermaid·블록 수식 | 기존 Markdown 렌더러로 해당 블록을 표시한다. |
| `$인라인 수식$` | `trust: false`로 KaTeX를 직접 렌더링한다. |
| frontmatter | 저장된 스냅샷의 `Properties`를 표시하고 클릭하면 현재 문서의 YAML을 드러낸다. |

인용·목록 안의 코드, 수식, 표를 렌더러에 넘길 때는 Lezer의 내용 범위와 원래 줄 간격으로 주변 컨테이너 표식을 제거한 블록 문자열을 만든다. 예를 들어 인용 안의 코드 복사 결과에 `>`가 들어가지 않게 한다. 이 정규화는 표시와 복사용 문자열에만 적용하고 편집기 문서와 위치를 변경하지 않는다.

Callout처럼 기존 렌더러가 담당하는 블록 안의 할 일도 같은 원문 편집 규칙을 따른다. 읽기 렌더러의 비활성 체크박스에 해당 블록의 Lezer `TaskMarker` 위치를 연결하고 조작할 때 원문 문자 하나만 바꾼다. 다른 줄을 입력해 블록 위치가 바뀌면 현재 문서에서 표식 위치를 다시 찾는다.

### 기존 렌더러를 사용하는 portal
표, Mermaid, 블록 수식과 callout은 자체 DOM 구현을 만들지 않고 기존 `Markdown`을 사용한다. frontmatter는 기존 `Properties`를 사용한다. CodeMirror 위젯은 컨테이너 DOM을 만들고 편집기별 저장소에 등록한다. 원래 React 트리가 `createPortal`로 그 안에 내용을 렌더링한다.

`createRoot`로 별도 React 트리를 만들면 react-query와 작업 공간 문맥이 끊어진다. Portal은 원래 문맥과 조회 캐시, 안전한 이미지 정책, 코드 복사·Mermaid 오류 표시·수식·callout 동작을 유지한다. 위젯의 `eq()`는 종류와 원문이 같은지 비교하므로 다른 줄의 입력 때문에 같은 블록을 매번 새로 마운트하지 않는다. 위젯을 제거하면 컨테이너 등록도 제거한다.

### StateField와 ViewPlugin의 함정
CodeMirror 6의 블록 위젯과 줄바꿈을 가리는 replacement는 편집기 높이와 viewport를 결정한다. 따라서 `StateField`에서 장식 집합을 만들고 `EditorView.decorations.from`으로 직접 제공한다. `ViewPlugin`에서 계산한 장식으로 블록이나 여러 줄을 대체하면 CodeMirror가 이를 거부한다. 현재 구현은 인라인 장식까지 같은 필드에서 계산하여 선택 영역과 초점 변경에 하나의 드러내기 규칙을 적용한다. 구문 트리의 백그라운드 파싱이 진행된 경우에도 필드를 다시 계산한다.

### 링크와 목차
렌더링된 링크를 클릭하면 편집기 소유자의 `onNavigate`로 대상과 Alt 상태를 전달한다. 같은 노트의 fragment, 해결된 노트 경로와 fragment, HTTP(S)·mailto를 구분한다. 없는 위키 링크와 여러 후보가 있는 링크는 임의 경로로 이동하지 않는다. 드러난 링크는 Ctrl/⌘ 클릭으로 이동한다. 노트 링크의 hover·키보드 초점 미리보기는 기존 `notes/resolve`와 `notes/content` 조회 키를 공유하고 제목과 본문 일부를 표시한다.

목차는 읽기 렌더러와 동일한 remark 변환을 거쳐 만든 HAST 제목의 텍스트에 문서별 `github-slugger` 중복 제거를 적용한다. 그래서 동일한 제목이 반복되면 읽기 화면의 `rehype-slug`와 같은 `-1`, `-2` ID를 얻는다. 링크 별칭, 엔티티와 인라인 코드도 같은 변환을 거친다. `rehype-slug`는 KaTeX보다 먼저 실행되므로 수식 제목의 ID에는 렌더링 전 TeX를 사용하며 이미지 alt는 ID에 포함하지 않는다. 목차 표시용 제목에는 이미지 alt를 포함한다.

제목 이동은 상위 스크롤 영역의 위쪽에서 16px 떨어진 위치를 사용하고 선택 영역을 바꾸지 않는다. 원문 접기 안의 제목이면 해당 CodeMirror 범위를 먼저 펼친다. Callout portal 안의 제목이면 해당 details를 펼치고 실제 제목 DOM의 위치를 사용한다. 상위 영역의 스크롤에 따라 활성 제목을 갱신한다.

CodeMirror 기본 스크롤러는 브라우저 scroll anchoring을 끈다. 자동 높이 편집기는 상위 영역이 스크롤을 소유하므로 이를 다시 켠다. 위쪽의 Mermaid가 비동기로 SVG를 표시하거나 위젯 높이가 바뀌어도 이미 이동한 제목이 viewport 안에서 밀려나지 않게 한다.

### 최소 차이 값 동기화
외부 `value` 변경은 현재 문서와 공통 접두사·접미사를 구하고 가운데 다른 범위만 바꾸는 트랜잭션으로 적용한다. CodeMirror가 기존 선택 영역을 변경 범위에 맞춰 이동하게 하고 상위 스크롤 위치를 보존한다. 외부 변경 전용 annotation을 붙여 `onChange`가 다시 호출되지 않게 한다.

`@uiw/react-codemirror`의 controlled wrapper는 외부 값 변경 시 문서 전체를 대체한다. 이 경로가 최소 차이 트랜잭션과 경쟁하지 않도록 편집기에서 `EditorView`와 문서 생명주기를 직접 소유하고 UIW의 기본 편집 확장만 재사용한다. 이미지 업로드의 삽입 위치도 진행 중 문서 변경에 따라 매핑하므로 업로드를 기다리는 동안 입력한 내용이 삽입 위치를 잃게 하지 않는다.

### 알려진 한계
- 지원하는 장식은 위 표의 구문이다. 원시 HTML은 실행하거나 미리보기로 해석하지 않는다. 참조형 링크 등 별도 장식이 없는 구문은 원문으로 편집한다.
- 복잡한 블록은 내용별 셀이나 도형을 직접 편집하는 편집기가 아니다. 원문을 드러내어 Markdown, Mermaid 또는 TeX를 수정한다.
- 속성 위젯은 서버가 마지막 저장에서 파싱한 frontmatter를 사용하므로 저장 전 YAML 변경이 속성 값에 즉시 반영되지 않는다.
- 중첩 컨테이너의 블록은 내용과 빈 줄을 유지하지만 코드·표·수식 위젯의 바깥 인용선과 목록 들여쓰기는 일반 줄 장식과 완전히 같지 않을 수 있다.
- 원문과 읽기 표시의 줄 수가 다른 블록, 숨긴 fence 줄과 여백은 읽기 렌더러의 문단 배치와 픽셀 단위로 같지 않다.
- 위키 링크는 읽기 렌더러처럼 일반 텍스트에서만 인식한다. 코드·수식·이미 연결된 문구 안의 문자열을 위키 링크로 해석하지 않는다.
- 인용·목록 안 블록 수식의 이어짐 판정은 Lezer 런타임의 `Line.depth`를 사용한다. 공개 타입에 없는 필드이므로 `@lezer/markdown` 버전은 명시적으로 고정하며 버전을 올릴 때 중첩 수식과 컨테이너 종료 동작을 확인한다.
