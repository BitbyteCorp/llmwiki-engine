# MCP 인터페이스
엔진은 지식 저장소의 모든 읽기·쓰기·검색 기능을 Streamable HTTP 기반 MCP로 제공한다.

## 배경

Claude Code, Codex, Hermes가 같은 지식 저장소를 활용하려면 각 클라이언트 전용 지식 인터페이스 대신 공통 인터페이스가 필요하다. MCP는 외부 클라이언트가 지식을 조회하고 저장하는 경로이며, [설치형 Skills](skills.md)는 이 경로의 설정과 사용 지침을 제공한다.

## 내용

### 제공 범위와 전송

지식 저장소의 읽기·쓰기·검색은 모두 MCP로 제공한다. 전송 방식은 Streamable HTTP다. 클라이언트 인증은 [인증과 권한](auth.md)의 OAuth 설계를 따른다.

### 도구 초안

다음 목록은 도구 초안이며, 특히 노트 목록과 색인 열람의 최종 도구 구성은 확정된 API가 아니다.

| 도구 초안 | 목적 |
| --- | --- |
| `search` | 하이브리드 검색으로 관련 지식을 찾는다. |
| `read_note` | 선택한 노트의 내용을 읽는다. |
| `list_notes` / `index` 열람 | 노트 목록과 진입점 색인을 살펴본다. |
| `write` | 자연어 지시나 원문을 지식 저장소에 반영하도록 제출한다. |
| `get_memory` | 메모리 파일의 내용을 읽는다. |
| `get_write_status` | [쓰기 작업](write-flow.md#비동기-작업과-상태-조회)의 상태를 조회한다. |

검색의 인덱스와 결과 구성은 [RAG](rag.md)에 기록한다.

### 쓰기 입력

클라이언트 LLM은 완성된 저장소 편집 결과가 아니라 자연어 지시나 원문을 `write`에 보낸다. Luna가 관련 지식을 찾고 기존 노트를 확장할지 새 노트를 만들지 결정한다. 예를 들어 기존 지식에 덧붙일 내용을 제출해도 클라이언트가 대상 노트와 편집 방식을 미리 확정할 필요는 없다. 작업 워크트리부터 반영 완료까지의 절차는 [쓰기 흐름](write-flow.md)을 따른다.

### 메모리 파일 리소스

`MEMORY.md`는 `get_memory` 도구뿐 아니라 MCP 리소스로도 노출한다. 세션 시작 시 메모리 파일을 읽는 규칙과 파일의 역할·위치는 [지식 저장소](knowledge-repository.md)에 기록한다.
