# 웹 버전
웹은 지식 저장소의 위키 탐색·읽기와 근거를 제시하는 질의응답을 제공한다.

## 배경

사용자는 MCP 클라이언트 없이도 브라우저에서 지식을 읽고 바로 질문할 수 있어야 한다. 웹은 같은 지식 저장소를 사람이 직접 탐색하거나 질문으로 활용하는 접점이다.

## 내용

### 위키 탐색과 읽기

웹에서 위키를 탐색하고 노트를 읽는다. 지식 저장소의 노트와 진입점 색인 구조는 [지식 저장소](knowledge-repository.md)를 따른다. 예를 들어 사용자는 직접 관련 노트를 찾아 읽거나, 아래 질의응답을 통해 질문에 필요한 지식을 찾는다.

### 질의응답

사용자는 웹에서 지식에 대한 질문을 입력한다. Luna는 에이전트형 RAG를 사용해 답변하고 근거 노트를 인용한다. 검색과 노트 읽기를 반복하는 동작은 [RAG](rag.md)에, 메모리 파일의 문맥 주입 규칙은 [지식 저장소](knowledge-repository.md)에 기록한다. 인용은 사용자가 답변의 근거 노트로 돌아가 내용을 확인할 수 있도록 하기 위한 것이다.

### 대화 기록과 학습

웹 질의응답 대화 기록은 DB에 저장하며 기본적으로 생성자만 접근한다. 소유자가 편집자나 조회자를 초대하면 해당 대화 구성원에게만 공유한다. 관리자라도 구성원이 아니면 대화와 생성 작업에 접근하지 못한다.

대화에서 지식으로 추출하는 대상은 사용자가 말한 사실과 정정뿐이다. Luna의 답변은 기존 위키에서 나온 지식을 다시 넣어 지식이 순환하게 만들 수 있으므로 학습 대상에서 제외한다.

반영은 [dreaming](dreaming.md#실행-시각과-입력)에서 하루치를 모아 배치로 수행한다. 대화에서 추출한 지식은 지식 저장소에 들어가며 저장된 경로의 [접근 규칙](access-control.md)을 따른다. Dreaming의 시스템 권한과 ACL 경계 간 정보 이동의 한계도 해당 문서에 기록한다.

### 변경 이력

`/history`의 기본 화면은 커밋·쓰기 작업·dreaming·원격 백업을 합친 타임라인이다. 유형·출처·경로 필터를 URL에 유지하고 불투명 `before` 커서로 이전 항목을 자동 또는 버튼으로 더 읽는다. 타임라인에서 경로를 필터링할 때는 `/history?view=activity&path=`를 사용한다. 공통 `main.updated`·`job.updated`·`dream.updated` 신호가 새 항목을 맨 위에 반영하며 새로 들어온 항목을 강조한다.

이력의 원천은 지식 저장소의 git 커밋과 DB의 쓰기 작업 기록이다. 커밋의 요청자·수행자 기록 규칙은 [쓰기 흐름](write-flow.md#요청자와-커밋-수행자의-구분)을 따른다. 잘못된 지식을 고치는 절차는 [정정 쓰기](write-flow.md#잘못된-지식의-정정)에 설명한다.

#### 노트별 이력과 비교

`/history?path=`는 `follow=1`로 이름 변경 이전의 커밋까지 읽으며 당시 경로와 이름 변경을 행에 표시한다. 작성자·요청자·커미터를 구분하고 커밋 trailer의 출처, 상대 시각과 절대 시각을 표시한다. `보기`는 당시 경로의 `/wiki/<path>?ref=<sha>`로 이동하고 `현재와 비교`는 현재 경로와 main을 비교한다. 체크박스로 두 버전을 골라 `/history/compare?base=&head=&path=`를 연다. 비교 화면은 SHA·git ref 입력과 이력 선택기를 제공하며 이전 커밋은 마지막 SHA를 `before`로 더 읽는다. 경로가 있는 비교는 양쪽 revision의 같은 경로를 비교하므로 이름 변경 전후의 경로가 다르면 추가·삭제 diff가 나타날 수 있다.

커밋 상세 `/history/commits/[sha]`는 병합 커밋의 부모 번호와 SHA를 선택하고 변경 파일과 연결된 작업을 표시한다. 공유 `DiffView`는 나란히·통합 모드를 브라우저에 저장하고 줄 번호·단어 단위 강조·접힌 미변경 영역·다중 파일 이동을 제공한다. 미변경 영역 펼치기는 patch 또는 전체 본문에 실제로 포함된 문맥만 펼친다. 바이너리와 이름만 변경된 파일은 텍스트 diff가 없음을 표시하고 큰 patch는 명시적으로 불러온다. 편집자 이상은 커밋 전체 또는 선택한 파일의 역변경을 미리 본 뒤 적용한다. 병합 커밋 되돌리기는 첫 번째 부모 기준이며 다른 부모를 보는 중에는 선택 파일 되돌리기를 막는다.

`/history/blame?path=&ref=`와 노트의 Blame 모드는 같은 `BlameView`를 사용한다. 연속된 같은 커밋의 줄을 묶고 작성 시각의 상대 나이에 따라 gutter 색을 표시한다. hover 또는 키보드 초점으로 제목·작성자·날짜·출처·작업 링크를 확인하고 짧은 SHA에서 커밋 상세로 이동한다.

#### 쓰기 작업과 dreaming·일기

`/jobs`는 `mine=1`로 자신의 작업을 조회하고 상태와 `before` 작업 ID를 URL에 유지한다. 서버가 상태 필터를 제공하지 않으므로 원본 페이지를 순회하여 오래된 일치 작업도 찾는다. `/jobs/[id]`는 저장된 단계 이벤트로 대기·준비·편집·커밋·병합·필요 시 충돌 해결·색인·정리·완료 또는 실패를 표시한다. 공통 `job.updated`로 갱신하며 주기적으로 폴링하지 않는다. 충돌 경로와 실제 이벤트만 표시하고 기록에 없는 해결 결과를 만들지 않는다. 편집자 이상인 소유자 또는 관리자는 실패 작업을 새 ID의 작업으로 재시도하고 대기 작업만 확인 후 취소한다.

`/dreams`는 실행 ID 커서로 기록을 더 읽고 `/dreams/[id]`는 입력 커밋 범위·요약·변경 파일·일기·최종 merge SHA·소요 시간·오류·push 결과를 표시한다. 이력 패널과 타임라인의 백업 배지는 마지막 성공한 원격 push의 경과 시간, 로컬 전용 건너뜀과 실패를 구분한다. 이 배지는 SQLite와 업로드를 포함하는 전체 백업의 상태가 아니다.

`/journal?date=YYYY-MM-DD`는 한국 날짜 기준 일기를 달력과 월별 목록으로 찾아 공유 Markdown 렌더러로 읽는다. 이전·다음 버튼은 일기가 있는 날만 건너뛰지 않고 실제 하루씩 이동한다. 일기 없는 날짜와 조회 실패를 구분하며 해당 날짜의 dreaming과 노트 커밋으로 이동한다. 이력 사이드바는 현재 노트의 최근 10개 이력과 타임라인·작업·dreaming·일기 링크를 실시간으로 제공한다. Ctrl/⌘ K 또는 Ctrl/⌘ Shift P의 명령 팔레트에서 현재 노트 이력·전체 타임라인·일기·dreaming 기록을 연다.

### 로그인과 관리 화면

웹은 로그인과 관리자용 관리 화면을 제공한다. 관리 화면에서 바꾸는 사용자·권한 설정과 첫 관리자 등록 절차는 [인증과 권한](auth.md)을 따른다.

#### 운영 콘솔

`/admin`은 관리자만 열 수 있으며 운영 개요·사용자·로그인 설정·감사 로그·접근 권한·내보내기 탭을 제공한다. 탭은 `?tab=overview|users|settings|audit|acl|export`로 직접 연다. 관리 사이드바는 큐·인덱스·dreaming의 간단한 상태와 관리·설정·가져오기 링크를 제공한다. 운영 개요는 `/api/admin/ops`와 `/readyz`를 읽고, 공통 `job.updated`·`index.updated`·`dream.updated` 이벤트로 갱신하며 별도 주기 조회를 하지 않는다.

운영 개요에서 큐 깊이·최장 대기 시간·실행 중 작업·최근 실패 작업과 재시도, 대기 중 작업 취소를 확인한다. 인덱스의 indexed/head SHA·동기화·미처리 벡터·임베딩 설정과 준비 여부·최근 오류를 표시하며, 증분·전체 재색인은 확인 뒤 실행한다. dreaming의 마지막·실행 중 기록과 수동 실행을 제공한다. 백업 표시는 dreaming의 원격 git push 결과이며 SQLite·업로드를 포함하는 전체 백업과 구분한다. 전체 백업은 오프라인 `llmwiki backup` CLI를 사용한다.

운영 개요의 `전체 쓰기 작업 보기`는 `/jobs`의 작업 목록으로 이동한다. 전체 활동 타임라인과 구분하며, 목록의 기본 범위는 [쓰기 작업 화면](#쓰기-작업과-dreaming일기)을 따른다.

감사 로그는 행위자 숫자 ID와 정확한 행위 문자열을 조합해 필터링하고 커서로 이전 기록을 더 읽는다. 사용자·권한·설정·토큰·운영 변경은 성공뿐 아니라 실패도 기록한다. 토큰 비밀값과 요청 원문은 표시하지 않는다. 탭은 방향키·Home·End로 이동한다.

#### 개인 설정과 API 토큰

모든 사용자는 `/settings`에서 `/api/me`의 계정·역할, 시스템·밝은·어두운 테마, 자신의 API 토큰과 MCP·Skill 연결 안내를 확인한다. 관리자는 전체 토큰 보기로 `all=1` 목록을 조회한다. `?section=tokens`와 `?section=export`는 해당 섹션으로 초점을 옮긴다. MCP 서버 주소는 서버의 `PUBLIC_URL`에 `/mcp`를 붙인 값이며, `llmwiki skill install claude-code|codex|hermes` 이후 각 클라이언트의 MCP 설정과 OAuth 로그인을 별도로 수행한다.

토큰 발급은 쿠키 로그인 세션에서만 가능하며 이름·독립적인 read/write 범위·선택적 미래 만료 시각을 입력한다. 비밀값은 발급 직후 한 번만 표시하고 복사·보관 후 명시적으로 지운다. 캐시나 브라우저 저장소에 비밀값을 보관하지 않으며 다시 조회할 수 없다. 폐기는 확인 뒤 적용하고 폐기된 Bearer 요청은 401을 받는다. 범위는 사용자 역할이나 폴더 접근 권한을 대체하지 않으며 REST API 토큰은 MCP OAuth 토큰과 다르다.

#### 원문 가져오기와 내보내기

`/imports`는 자신의 가져오기 목록을 제공하며 관리자는 전체 목록을 확인한다. 편집자 이상은 URL·텍스트·PDF/Markdown/텍스트 파일·Obsidian vault ZIP·Notion export ZIP을 추가한다. 파일은 `purpose=import` multipart 업로드와 진행률을 거쳐 원문 수집 API로 연결하며 선택적인 Luna 통합 지침을 함께 보낸다. URL·문서·텍스트는 20 MiB, ZIP은 압축·해제 합계 100 MiB 제한을 적용한다. 사설 네트워크 URL·잘못된 파일·크기 제한 오류는 원문 수집 실패로 구분해 표시한다.

목록과 상세 서랍은 추출·대기·실행·완료·실패·취소 상태를 표시하며 연결된 `job.updated` 이벤트로 갱신한다. 상세에서 불변 raw 경로·쓰기 작업·오류를 확인한다. raw의 바이너리 경로는 기록 그대로 유지하며 해당 경로를 노트 링크로 열었을 때 Markdown 본문이 없는 파일은 노트 조회 오류가 될 수 있다. 이전 목록은 마지막 import ID를 커서로 더 읽는다. 서랍은 Escape로 닫고 원래 요소로 초점을 복원한다.

설정과 관리의 내보내기 화면은 노트 트리 또는 직접 입력한 경로 접두사로 현재 커밋된 main을 ZIP으로 다운로드한다. ZIP에는 `manifest.json`이 포함된다. Git bundle은 전체 main 이력을 다운로드하며 부분 경로와 함께 선택할 수 없다. 지식 파일 내보내기는 대화·사용자 DB·임시 업로드의 전체 백업이 아니다. Ctrl/⌘ K 또는 Ctrl/⌘ Shift P의 명령 팔레트에서 설정·API 토큰·가져오기·내보내기와 관리자용 운영 현황을 연다.

### 디자인

웹은 shadcn/ui 기반으로 깔끔하게 레이아웃을 맞춘다.

`components.json` 설정은 다음과 같다.

| 설정 | 값 |
| --- | --- |
| `style` | `base-nova` |
| `baseColor` | `neutral` |
| `cssVariables` | 사용한다. |
| `iconLibrary` | `lucide` |
| `menuColor` | `default` |
| `menuAccent` | `subtle` |

엔진 웹은 Next.js 16, React 19, Tailwind CSS 4, `@base-ui/react`를 사용한다. App Router가 화면 경로와 공통 레이아웃을 관리하며 Nest 서버가 같은 Node 프로세스 안에서 Next의 요청 핸들러를 호출한다. 별도 Next 서버 프로세스나 컨테이너를 두지 않는 이유와 서버 경로 분리는 [전체 구성](architecture.md)에 기록한다.

### 구현된 웹 화면

`web/`는 별도 패키지가 아닌 단일 루트 패키지 안의 Next 프로젝트 디렉터리다. UI 의존성은 루트에서 설치하며 `pnpm exec next build web`로 `web/.next`에 빌드한다. 평소 개발과 실행은 Nest와 Next를 한 프로세스로 묶는 루트 스크립트를 사용하며 명령은 [개발 환경](development.md)에 기록한다. 클라이언트 화면은 같은 origin의 `/api`와 `/auth`를 사용하므로 별도 개발 프록시가 필요하지 않다.

화면은 React 19, Next.js App Router, TanStack Query, Tailwind CSS 4로 구성한다. `web/app`은 라우트와 레이아웃, `web/pages-ui`는 클라이언트 화면, `web/components`와 `web/lib`는 공통 UI와 API·스트림 처리를 담당한다. 최상위 레이아웃에 서버 상태 캐시와 테마 제공자를 두고 콘솔 레이아웃에서 로그인과 관리자 접근을 확인한다. 중립색, 얇은 테두리, LINE Seed Sans KR와 Geist Mono 글꼴을 유지하면서 좁은 활동 표시줄, 크기를 조절하는 기본 사이드바, 탭이 있는 본문, 하단 상태 표시줄로 작업 공간을 구성한다. 활동 표시줄에는 탐색기·검색·대화·이력을 배치하고 관리자에게만 관리를 표시한다. 모바일 사이드바는 본문을 대체하지 않는 모달 서랍이며 Escape로 닫고 원래 버튼으로 초점을 돌려준다. 헤더의 사용자 메뉴에서 현재 계정과 역할을 확인하고 로그아웃한다.

`/api/me`가 401을 반환하면 Google 로그인 화면을 표시한다. `/login`에서도 같은 로그인 화면을 직접 열 수 있다. 로그인 버튼은 `/auth/google/login`으로 이동하며, 로그인 후 돌아갈 앱 경로를 `next`에 전달한다. 다른 API에서 세션 만료를 받으면 캐시를 지우고 로그인 화면으로 전환한다.

노트 경로는 `/wiki/[...path]`로 유지하며 각 경로 조각을 URL 인코딩한다. `/wiki`로 들어오면 `index.md`를 우선 선택한다. 파일 트리는 노트 본문과 분리된 탐색기 패널에 있어 노트를 바꾸어도 상태를 유지한다. 노트의 폴더 경로는 클릭 가능한 breadcrumb로 표시하며 폴더를 누르면 탐색기에서 해당 위치를 드러낸다. 마지막 경로 조각에는 frontmatter 제목을 표시한다. 노트 헤더에서 즐겨찾기와 해당 경로의 변경 이력을 열 수 있다.

현재 Next.js 16의 클라이언트 경로 이동에서 동적 경로 매개변수는 URL 인코딩된 값으로 전달된다. 노트의 각 경로 조각과 대화·작업·커밋 식별자는 화면에서 한 번만 디코딩한 뒤 API에 넘긴다. API 클라이언트가 요청 경로를 다시 인코딩하므로 이 처리를 생략하면 한글 노트 경로가 이중 인코딩되며, 두 번 디코딩하면 파일명에 들어간 `%20` 같은 문자열이 달라진다.

검색 화면의 검색어·필터·소제목 연결과 검색·백링크·태그 패널의 동작은 [검색과 지식 탐색](#검색과-지식-탐색)을 따른다. Luna 화면의 대화 목록·실시간 답변·문맥·첨부·초안 적용은 [Luna 대화 작업 공간](#luna-대화-작업-공간)을 따른다.

변경 이력 화면과 노트별 비교·되돌리기·Blame, 쓰기 작업 단계, dreaming 보고서와 일기 탐색의 경로와 동작은 [변경 이력](#변경-이력)을 따른다. 관리 화면 `/admin`은 사용자 추가·역할 변경·삭제와 등록 이메일 제한·허용 도메인 설정을 제공한다. 마지막 관리자 보호와 같은 서버 오류는 화면에 표시하며, 관리자가 아닌 계정으로 직접 관리 경로에 들어오면 접근 오류를 표시한다.

### Luna 대화 작업 공간

활동 표시줄의 대화 패널은 구성원 대화를 최근 활동 순으로 표시한다. 제목과 메시지 검색은 `?q=`를 사용하며 결과에 최대 240자의 본문 조각을 표시한다. 소유자와 편집자는 목록에서 제목을 직접 바꾸고 Enter로 저장하거나 Escape로 취소한다. 소유자만 확인 후 대화를 삭제한다. 구성원이 둘 이상이면 공유 배지를 표시하며 `conversation.updated`로 목록과 현재 대화를 갱신한다.

답변은 `generation`·`status`·`tool`·`citation`·`delta`·`usage`·`done`·`error`를 모두 읽는다. 검색어와 읽은 노트 경로를 접을 수 있는 근거 확인 과정에 표시한다. 실행 중 답변을 다시 열거나 다른 화면에서 열면 연결된 `generationId`로 전체 이벤트를 재생하고 실시간 생성에 이어 붙인다. 네트워크가 끊기면 마지막 이벤트 이후부터 자동 재연결한다. 화면 이동은 생성 관찰만 종료하며 중지 버튼과 Escape만 서버 생성 취소를 요청한다. 생성 ID가 아직 도착하지 않았을 때 누른 중지도 ID 수신 직후 적용한다.

메시지는 위키와 같은 Markdown 렌더러를 사용한다. 인용 번호에는 소제목과 본문 미리보기를 제공하며 현재 SHA와 다르면 변경됨 표시와 `?ref=`가 있는 과거 노트 링크를 사용한다. 모델·추론 강도·입력·출력·추론 토큰은 답변 하단에 작게 표시한다. 실패·취소·서버 중단 상태는 부분 답변으로 표시하고 다시 시도할 수 있다. 질문 수정과 답변 재생성은 이후 대화가 교체된다는 확인을 요구한다. 복사·새 노트로 저장·기존 노트에 적용을 메시지 동작에서 실행한다.

입력은 여러 줄을 지원한다. Enter는 전송, Shift+Enter는 줄바꿈이며 IME 조합 중 Enter는 전송하지 않는다. 비어 있는 입력의 위쪽 화살표는 마지막 질문 수정을 연다. 파일 버튼·대화 영역의 끌어 놓기·클립보드 이미지 붙여넣기로 최대 10개, 각 20 MB의 이미지를 비롯한 PDF·텍스트·Markdown을 첨부한다. 업로드 진행률과 서버의 크기·형식 오류를 입력 안에 표시하고 전송 전에 제거할 수 있다. 이미지는 확대 창으로 열고 나머지 첨부는 파일 카드와 다운로드 링크로 표시한다. 업로드 다운로드는 소유자만 가능하므로 공유 대화의 다른 구성원은 첨부 접근 오류를 볼 수 있다.

노트 또는 선택한 문장에 대한 Luna 질문은 `askLuna({notePath,ref?,selection?})`로 새 대화를 열고 제거 가능한 고정 문맥을 전달한다. `@` 추천이나 `/note <path>`도 노트를 고정한다. 고정 문맥은 브라우저 세션의 대화별 상태로 유지하며 후속 질문에도 전송하고 제거하면 해제한다. `/search <q>`는 현재 대화를 유지하면서 입력 아래 검색 결과와 전체 검색 링크를 표시한다. `/save`는 마지막 완성 답변의 새 노트 초안을 열고 `/help`는 입력 도움말을 표시한다. 모델과 추론 강도 선택은 서버가 제공한 허용 목록만 사용하며 기본값은 요청에서 생략한다.

새 노트 초안은 제안 경로를 수정할 수 있고 기존 노트 적용은 대상 노트를 선택한다. 초안 요청은 저장하지 않는다. 검토 창에서 제안 본문을 편집하고 공통 DiffView의 분할·통합 비교로 변경을 확인한 뒤 반환된 `baseSha`로 `PUT /api/notes`를 실행한다. 409 충돌은 덮어쓰지 않고 최신 원문을 기준으로 초안을 다시 제안하도록 안내한다. 성공 알림은 노트·쓰기 작업·커밋 링크를 제공한다. 첨부의 위키 자산으로 저장은 현재 커밋을 자동 조회해 `assets/` 경로로 저장하며 충돌 시 명시적으로 최신 기준을 다시 읽는다. 위키 쓰기와 자산 저장은 [폴더별 접근 제어](access-control.md)의 대상 경로 쓰기 권한도 요구한다.

공유 창은 구성원을 표시하고 소유자만 등록된 이메일을 편집자·조회자로 추가하거나 역할을 바꾸고 제거한다. 조회자는 대화를 읽지만 질문을 보낼 수 없다. 현재 창에 초점이 있는 동안 10초마다 접속 상태를 갱신하고 입력 중 상태를 전송한다. 다른 구성원의 아바타와 입력 중 표시를 실시간으로 갱신하며 초점 상실·화면 종료 후 heartbeat를 멈추고 서버의 30초 TTL 뒤 접속 목록에서 사라진다.

Ctrl/⌘ Shift O는 새 대화를 연다. Ctrl/⌘ K는 기존 전역 명령 팔레트를 유지한다. 팔레트의 새 대화·대화 검색·현재 노트로 대화 시작은 각각 새 스레드, 대화 검색 입력, 현재 노트와 읽은 SHA를 고정한 새 대화를 연다.

생성 ID가 포함된 서버 응답을 받을 때까지 입력과 첨부를 보존하며 최초 제출이 거절되면 다시 편집하고 전송할 수 있다. 선택한 문맥이 32,000자를 넘으면 전송 전에 입력 안에 길이 오류를 표시하고 원문을 임의로 자르지 않는다. Escape는 열린 확대·공유·검토 창이나 IME 조합을 먼저 처리하며 이때 답변을 취소하지 않는다. 모바일 경계 전환은 본문을 다시 마운트하지 않으므로 작성 중 질문·편집한 초안·열린 검토 창을 유지하고 데스크톱 사이드바 너비와 접힘 상태도 복원한다.

### 작업 공간과 패널

`web/components/workspace/registry.tsx`의 패널 목록에 식별자·제목·아이콘·기본 경로·렌더러·관리자 여부를 등록한다. 탐색·검색·백링크·태그·대화·이력·관리 패널은 이 목록을 공유하며 셸 구조를 다시 만들지 않는다. 백링크 패널을 열어도 현재 노트 경로는 유지한다.

탐색기는 경로와 이미 읽은 노트 제목을 필터링하고 폴더 확장 상태를 유지한다. 선택한 파일의 상위 폴더를 자동으로 펼치고 활성 파일을 표시한다. 목록 조회 오류는 빈 저장소와 구분하고 다시 시도 버튼을 제공한다. 최근 노트는 최대 30개이며 별표로 즐겨찾기를 바꾼다.

한 번 연 노트는 기울임꼴 미리보기 탭이 되며 다음 미리보기 노트로 대체된다. 두 번 클릭하거나 Ctrl/⌘ 클릭하면 탭을 고정한다. 탭 메뉴에서 고정·닫기·다른 탭 닫기를 실행하며 가운데 마우스 버튼으로도 닫는다. 닫은 탭은 최대 20개까지 다시 연다. 활성 기본 탭은 정식 노트 URL을 유지한다. 오른쪽 분할은 독립된 노트와 읽기 위치를 가지며 Alt 클릭으로 다른 노트를 연다. 분할 안의 노트 링크는 분할 안에서만 이동한다. 모바일에서는 두 노트를 세로로 배치한다. 마지막 탭을 닫으면 `/wiki?empty=1`에서 열린 노트가 없음을 표시하고 색인을 다시 여는 버튼을 제공한다.

사이드바 너비·접힘·활성 패널, 탐색기 필터·폴더 확장, 열린 탭·분할·최근 노트·즐겨찾기·읽은 제목을 계정 ID별 localStorage 키에 저장한다. 이 상태와 즐겨찾기는 해당 브라우저에만 있으며 서버나 다른 기기로 동기화하지 않는다. localStorage를 사용할 수 없어도 현재 세션 안의 탐색은 동작한다.

하단에는 기본 노트 경로, 읽은 스냅샷의 짧은 `updatedSha`, 본문 단어·줄 수, 테마와 실시간 연결 상태를 표시한다. 연결 표시는 공통 `useLiveConnection` 훅을 사용하며 셸에서 별도 SSE 연결을 열지 않는다.

### 노트 작성과 파일 작업

`/api/me`의 편집자·관리자에게만 편집과 파일 변경 작업을 표시한다. 조회자는 노트를 읽고 과거 버전·줄별 이력을 확인하거나 Luna에게 질문한다. 노트는 읽기, CodeMirror 원문 편집, 원문과 실시간 미리보기를 함께 표시하는 모드로 전환한다. 편집기는 밝은·어두운 테마, Markdown과 fenced 코드 언어, `[[` 위키 링크 자동완성을 지원한다. 속성과 목차는 읽기와 미리보기에서 유지한다.

변경한 탭은 자동으로 고정되고 탭과 하단 상태에 수정 표시를 남긴다. 상태 표시줄에는 보기·편집 모드, 저장 중·저장됨·충돌 상태와 편집 커서의 줄·열을 표시한다. Ctrl/⌘ S로 커밋 메시지와 함께 저장하며 기본 메시지는 `docs(wiki): update <제목>`이다. Escape와 변경 버리기는 저장하지 않은 내용을 확인 후 버린다. 탭 닫기·다른 노트나 패널 이동·뒤로 가기·페이지 종료에서도 저장하지 않은 변경을 확인한다. 초안은 브라우저 저장소에 영구 보관하지 않는다.

저장은 `PUT /api/notes`에 `path`, `content`, 편집을 시작한 `baseSha`, `message`를 보낸다. 다른 작성자가 같은 노트를 바꿔 `409 stale_note`가 발생하면 기준 버전과 내 변경, 기준 버전과 최신 저장소 내용을 공통 DiffView로 비교한다. 최신 버전 불러오기, 내 내용 복사, 명시적인 확인 후 내 내용으로 덮어쓰기를 제공한다. `main.updated`에 열린 경로가 포함되면 수정하지 않은 노트는 그 자리에서 새로 읽고 알림을 표시하며, 수정 중인 노트는 초안을 유지하고 `다른 곳에서 변경됨` 배너에서 비교한다.

탐색기의 도구 모음과 파일·폴더 메뉴에서 새 노트를 만들며 경로와 제목·태그를 입력한다. 새 노트에는 `title`, `tags`, `updated` frontmatter를 넣는다. 폴더는 가상 위치로 먼저 선택하며 첫 노트를 저장해야 저장소에 남는다. 파일 메뉴는 오른쪽 클릭, Menu 키·Shift F10, 모바일의 더보기 버튼으로 연다. F2는 파일명을 인라인으로 바꾸며 이동은 폴더 선택기나 폴더로 끌어 놓기로 실행한다. 이름과 경로를 바꾸면 탭·URL·최근 노트·즐겨찾기를 함께 바꾸지만 본문에 작성한 위키 링크는 자동 수정하지 않는다. 삭제 확인에는 `/api/links`에서 읽은 역링크 수를 표시한다. 경로·위키 링크 복사와 해당 파일의 이력 열기도 제공한다.

이동 대상이 이미 있으면 별도로 교체를 확인한다. 현재 서버 접점은 원자적인 덮어쓰기 이동을 제공하지 않으므로 기존 대상 삭제와 원본 이동을 두 커밋으로 실행한다. 두 번째 단계가 실패해도 원본은 남으며 최신 SHA로 다시 시도한다. 삭제한 대상은 변경 이력에서 복원한다.

편집기에 PNG·JPEG·GIF·WebP 이미지를 붙이거나 끌어 놓으면 chat 목적 업로드를 만든 뒤 `assets/<날짜>/<이름>`에 저장하고 노트 기준 상대 이미지 링크를 넣는다. 이미지 저장은 노트 저장과 별도 커밋이므로 초안을 버려도 이미지 자산은 남는다. `GET /api/notes/raw?path=&ref=`는 assets 아래의 실제 이미지 바이트를 지정한 커밋에서 읽고 실제 형식의 Content-Type과 `nosniff`를 반환한다. 인증과 폴더 읽기 권한을 적용하며 경로 탈출·심볼릭 링크·HTML·SVG·지원하지 않는 형식은 거절한다. 렌더러는 노트 기준 상대 assets 경로와 과거 버전의 ref를 이 접점에 전달한다.

`/wiki/<경로>?ref=<SHA>`는 작성자·날짜·짧은 SHA와 읽기 전용 배너를 표시한다. 현재 버전 열기와 `/history/compare?base=<ref>&head=main&path=<경로>` 비교를 제공한다. 편집자 이상은 현재 버전과 복원 내용을 먼저 비교하고 확인한 뒤 현재 `baseSha`로 저장하며 `revert(wiki): restore <경로> to <짧은 SHA>` 커밋을 남긴다. 줄별 이력 토글은 공통 BlameView를 표시한다. 노트 전체의 `이 노트에 대해 묻기`와 선택한 본문의 `Luna에게 묻기`는 경로·스냅샷·선택문을 새 Luna 대화의 고정 문맥으로 넘긴다. 명령 팔레트에서도 새 노트, 편집 전환, 저장, 이름 바꾸기, 삭제, Blame 토글, Luna에게 묻기를 실행한다.

### 검색과 지식 탐색

`/search`와 사이드바 검색 패널은 입력이 300ms 동안 멈추면 제목 제안과 전체 검색을 실행한다. 새 입력은 TanStack Query의 AbortSignal로 이전 요청을 취소하며 한글 IME 조합 중에는 검색과 키보드 선택을 실행하지 않는다. 검색 화면은 `q`, `folder`, `tags`, `from`, `to`, `author`를 URL에 저장하므로 링크 공유와 뒤로·앞으로 이동에서 같은 조건을 복원한다. 폴더는 노트 트리에서 선택하고 태그는 색인의 노트 수와 함께 여러 개를 선택한다. 선택한 태그는 모두 포함해야 하며 작성자 조건은 마지막 수정 커밋의 이름·이메일을 찾는다. 수정일 종료에 날짜만 넣으면 UTC 기준 그날 전체를 포함한다.

결과에는 제목·경로 breadcrumb·소제목·태그·마지막 수정 시각을 표시한다. 서버의 UTF-16 highlight 범위를 본문 조각의 `<mark>`로 렌더링하고 결과를 열면 `/wiki/<path>#<anchor>`에서 해당 소제목으로 이동한다. ↑·↓로 제목 제안과 결과를 선택하고 Enter로 연다. Ctrl/⌘ Enter 또는 나란히 열기로 결과를 분할에 열며 검색 화면에서 실행하면 최근 기본 노트로 돌아간다. 다음 결과는 `nextCursor`로 스크롤할 때 자동 조회하며 직접 더 불러오기와 자동 조회 끄기도 제공한다. 커서는 5분 뒤 만료할 수 있으므로 오류 상태에서 처음부터 검색하거나 해당 페이지를 재시도한다.

의미 검색을 사용할 수 없으면 키워드 검색으로 표시하며 API 키 없음·임베딩 서비스 실패·벡터 모델/차원 불일치·색인 지연의 원인을 각각 알린다. 의미 검색이 준비되면 의미 + 키워드 표시를 사용한다. 검색 결과는 `index.updated`에서 다시 읽으며 공용 실시간 스트림만 사용한다.

백링크 패널은 현재 노트의 역링크·나가는 링크·미해결 링크와 의미상 유사를 구분한다. 의미상 유사는 명시적인 링크의 목록이 아니며 임베딩이 준비되지 않았을 때 빈 결과일 수 있다. 편집자 이상은 미해결 링크에서 대상 경로가 채워진 새 노트 대화상자를 열고 조회자는 대상 노트의 빈 상태를 연다. 패널의 주변 그래프는 링크 방향을 표시하며 전체 화면 지역 그래프로 연결한다. `main.updated`와 `index.updated`에서 링크·유사 노트·태그·그래프·중복 후보를 다시 읽는다.

태그 패널과 `/tags`는 이름 필터와 태그별 노트 수를 제공하며 `/tags/[tag]`에서 해당 노트를 읽거나 분할에 연다. 노트 속성의 태그 배지도 이 경로로 연결한다. 태그 경로는 한 번만 디코딩하여 한글과 리터럴 `%` 이름을 보존한다.

`/graph`는 클라이언트 전용 force graph와 키보드로 사용할 수 있는 노트 목록을 제공한다. 전체 그래프는 고립된 노트도 포함하며 `path`를 지정하면 그 노트 주변의 양방향 연결을 `depth` 1~5 슬라이더로 제한한다. 제목·경로 검색 뒤 초점 이동, 노트 클릭, hover 제목·경로, 전체 맞춤을 제공한다. 색상은 최상위 폴더, 크기는 연결 수, 화살표는 링크 방향을 나타낸다. 어두운 테마에 맞는 색상을 사용하며 큰 그래프는 축소 시 제목을 숨기고 배치 계산은 최대 6초 뒤 멈춘다.

`/search/duplicates`는 중복 후보의 정확한 내용 일치·의미 유사 이유와 점수, 양쪽의 일치 구절과 소제목 링크를 표시한다. 비교는 왼쪽 노트를 고정 기본 탭, 오른쪽 노트를 분할로 열며 자동 병합·삭제하지 않는다. 점수는 확정 판정이 아니며 의미 기반 후보는 준비된 임베딩만 사용한다. 검색 헤더와 명령 팔레트에서 그래프 열기·태그 보기·백링크 패널·중복 후보로 이동한다.

### 단축키와 테마

| 단축키 | 동작 |
| --- | --- |
| Ctrl/⌘ P | 경로 퍼지 검색과 서버 제목 제안을 제공하는 빠른 열기를 연다. `#`는 소제목 검색, `>`는 명령 검색이다. |
| Ctrl/⌘ K, Ctrl/⌘ Shift P | 명령 팔레트를 연다. |
| Ctrl/⌘ Shift T | 마지막으로 닫은 탭을 다시 연다. |
| Ctrl/⌘ \\ | 노트 분할을 전환한다. |
| `?`, F1 | 단축키 도움말을 연다. `?`는 입력 영역 밖에서만 동작한다. |
| ↑·↓, Enter, Escape | 팔레트 항목 선택·실행·닫기를 수행한다. |
| Ctrl/⌘ Enter | 검색 결과나 빠른 열기 결과를 분할에 연다. |

명령 팔레트는 노트 열기, 패널 전환, 사이드바 전환, 분할, 탭 고정·닫기·다른 탭 닫기·다시 열기, 현재 노트 이력, 즐겨찾기, 탐색기 위치 표시, 테마 전환을 제공한다. 한글 등 IME 조합 중에는 단축키나 Enter 선택을 실행하지 않는다. 모달은 초점을 가두고 닫을 때 원래 요소로 복원한다.

`next-themes`로 시스템·밝은·어두운 테마를 제공하며 `llmwiki.theme`에 브라우저 선호를 저장한다. 초기 HTML의 테마 스크립트가 수화 전에 클래스를 적용하므로 잘못된 테마가 먼저 번쩍이지 않는다. 코드·diff·수식·Mermaid도 어두운 배경에서 구분되는 색을 사용한다.

### 노트 렌더링과 링크

GFM 표·목록과 함께 `rehype-highlight` 코드 강조와 복사 버튼, `remark-math`·`rehype-katex` 수식, Mermaid fenced block을 표시한다. Mermaid는 클라이언트에서만 동적으로 불러오고 테마 변경 시 다시 그린다. strict 보안 모드를 사용하며 파싱 실패 시 오류와 원문을 표시한다. 원시 HTML은 실행하거나 렌더링하지 않는다.

`> [!note] 제목` 같은 Obsidian callout을 표시하며 종류 뒤의 `-`는 처음 접힘, `+`는 처음 펼침인 접이식 callout을 만든다. 제목에는 `rehype-slug` ID와 앵커 링크를 붙인다. 노트별 목차는 실제 렌더링된 제목에서 만들며 IntersectionObserver와 스크롤 위치로 활성 제목을 표시하고 클릭 시 해당 읽기 영역 안에서 이동한다.

frontmatter 속성 패널은 제목·날짜·중요도 같은 알려진 필드와 문자열·숫자·불리언 같은 스칼라 필드를 안전하게 표시하며 임의 객체를 HTML로 해석하지 않는다. 태그 배지는 `/tags/<tag>`로 연결한다.

`[[폴더/노트#제목|별칭]]`과 상대 `.md` 링크는 경로·별칭·fragment를 유지하며 앱 안에서 연다. 공백을 포함한 제목 fragment는 렌더링 제목과 같은 slug로 바꾼다. 코드 안의 위키 링크 문자열은 변환하지 않는다. 해결된 링크는 hover 또는 키보드 초점에서 기존 노트 내용 API를 사용한 제목·본문 미리보기를 제공하며 조회 캐시를 공유한다. 없는 링크와 같은 이름의 후보가 여러 개인 링크는 서로 다른 표시로 남겨 임의 노트로 이동시키지 않는다. 이름 해석은 기존 `{path}` 응답과 `{path,candidates}` 응답을 모두 읽는다.

### REST API와 저장 규칙

웹 API는 `/api` 아래에 있으며 웹은 세션으로 인증한다. 같은 API는 `SessionGuard`를 통해 REST Bearer 토큰도 받으며 읽기·쓰기 scope와 만료·회수 정책은 [인증과 권한](auth.md)을 따른다. `viewer`도 위키·검색·이력·질의응답을 이용할 수 있고, `/api/admin`은 `admin`만 이용할 수 있다. 오류는 HTTP 상태와 함께 `{error:{code,message}}` 형태로 반환한다. 마지막 관리자를 삭제하거나 다른 역할로 내리려 하면 `409`와 `last_admin` 코드를 반환한다.

`src/api/api.module.ts`는 현재 사용자·노트·검색·이력·쓰기 작업·대화·관리 API뿐 아니라 업로드·생성 작업·Luna 모델·링크·그래프·태그 컨트롤러도 등록한다. 각 컨트롤러는 `SessionGuard`로 웹 세션 또는 REST Bearer 토큰을 검사하며 역할 제한이 필요한 접점에는 `RolesGuard`와 `@Roles`를 적용한다. 입력은 `api.dto.ts`의 Zod 스키마와 공용 `ZodValidationPipe`로 검증하고 오류 응답은 전역 HTTP 예외 필터가 만든다. `NotesService`는 노트 읽기와 이름 해석을, `HistoryService`는 git 이력과 쓰기 작업 연결·요청자 표시를 담당한다.

| 접점 | 용도 |
| --- | --- |
| `GET /me` | 현재 사용자를 반환한다. |
| `GET /notes/tree`, `/notes/content?path=`, `/notes/resolve?name=` | main의 마크다운 목록, 원문·frontmatter·본문·`updatedSha`, 위키 링크의 노트 경로를 반환한다. |
| `GET /search?q=&folder=&tags=&from=&to=&author=&cursor=&limit=` | 검색 모드·축소 원인·소제목 anchor·highlight와 다음 커서를 반환한다. |
| `GET /search/suggest`, `/search/similar?path=`, `/search/duplicates` | 제목 제안·노트의 의미상 유사 목록·중복 후보를 반환한다. |
| `GET /links?path=`, `/graph?path=&depth=`, `/tags`, `/tags/notes?tag=` | 노트 연결·전체 또는 지역 그래프·태그와 태그별 노트를 반환한다. |
| `GET /history?path=&limit=&before=`, `/history/commits/:sha` | 전체 또는 노트별 커밋 목록과 커밋·파일 변경·patch·연결된 쓰기 작업을 반환한다. |
| `GET /jobs?mine=1&limit=&before=`, `/jobs/:id` | 요청자 이메일·이름을 포함한 쓰기 작업 목록과 작업별 커밋을 반환한다. |
| `GET /conversations?q=`, `POST /conversations`, `GET`, `PATCH`, `DELETE /conversations/:id` | 구성원 대화의 검색·생성·조회·제목 변경·소유자 삭제를 처리한다. |
| `POST /conversations/:id/messages`, `PATCH /conversations/:id/messages/:mid`, `POST .../:mid/retry`, `POST .../:mid/regenerate` | 질문 제출·수정·재시도·답변 재생성을 SSE로 전달한다. |
| `GET /generations/:id/events`, `POST /generations/:id/cancel` | 생성 이벤트 재연결과 명시적인 중지를 처리한다. |
| `GET /luna/models` | 허용 모델과 기본 모델, 요청 가능한 추론 강도와 서버 기본 강도를 반환한다. |
| `GET`, `POST /conversations/:id/members`, `DELETE /conversations/:id/members/:userId`, `POST /conversations/:id/presence` | 구성원과 30초 TTL 접속 상태를 관리한다. |
| `POST /uploads`, `GET /uploads/:id`, `POST /uploads/:id/save` | 첨부 업로드·소유자 다운로드·assets 저장을 처리한다. |
| `POST /conversations/:id/messages/:mid/proposal` | 답변에서 새 노트나 수정 초안을 만들며 저장하지 않는다. |
| `/admin/users`, `/admin/settings` | 사용자와 역할, 허용 목록 사용 여부와 허용 도메인 설정을 관리한다. |

표의 경로 앞에는 `/api`를 붙인다. 노트 내용은 지정한 `ref` 또는 생략 시 main HEAD를 커밋 SHA로 고정한 뒤 같은 커밋에서 읽으므로 `updatedSha`는 본문과 일치하는 저장소 스냅샷이다. `path`는 저장소 상대 `.md` 경로이며 절대 경로·상위 경로·git 메타데이터 경로는 거절한다. 위키 링크 이름 해석은 폴더 경로를 받을 수 있고 `#fragment`를 제외한다. 응답은 `{path,candidates}`이며 같은 basename 후보가 여러 개이면 `path:null`과 후보 목록을 반환하여 사용자가 선택한다. 후보가 없으면 `404`다.

목록의 `limit`은 기본 50, 최대 100이다. 변경 이력의 `before`는 마지막 커밋 SHA이며 해당 커밋보다 오래된 결과를 요청한다. 쓰기 작업의 `before`는 마지막 작업의 ID다. 커밋과 쓰기 작업은 작업의 `commits` 배열 또는 `mergeSha`로 연결한다. 요청자가 삭제되어도 쓰기 작업 이력은 남으며 요청자 표시는 이메일 대신 `deleted user`, 이름 대신 `null`을 반환한다.

대화는 `conversations`, 메시지는 `messages`, 구성원은 `conversation_members`, 생성 작업은 `generations`, 순서가 있는 SSE 프레임은 `generation_frames`에 저장한다. 대화 목록은 최근 활동 순서이며 `q`는 제목과 메시지의 부분 문자열을 검색해 최대 240자 `snippet`을 추가한다. 메시지는 삽입 순서다. 구성원이 아닌 사용자의 요청은 관리자도 `404`, 대화 조회자의 변경 요청은 `403`이다. 소유자만 대화 삭제와 구성원 변경을 수행하며 자기 소유권을 제거할 수 없다. 구성원 편집자는 제목·메시지를 변경한다. 전역 `viewer`도 자신이 만든 대화의 소유자로 질문할 수 있다.

제목 없이 만든 대화는 첫 질문의 공백을 정리하고 Unicode 문자 80개까지 잘라 제목을 정한다. 명시적 제목은 200자, 질문은 100,000자이며 빈 질문은 거절한다. `PATCH /conversations/:id` 입력은 `{title}`이다. `GET /conversations/:id`는 `{conversation,messages}`이며 메시지는 `{id,role,content,citations,attachments,context,status,usage,model,effort,generationId,createdAt}`이다. `generationId`는 assistant 메시지에 연결된 생성 ID이며 연결이 없으면 `null`이다. 이를 사용하면 다른 기기나 새로 연 화면에서도 실행 중 생성에 연결할 수 있다. `status`는 `completed|running|failed|cancelled|interrupted`, `usage`는 `{inputTokens,outputTokens,reasoningTokens}|null`, `context`는 `{notePath,ref?,selection?}|null`이다. `citations`는 `{path,heading?,anchor?,excerpt?,sha?}` 객체 배열이다.

`POST /conversations/:id/messages` 입력은 `{content,attachments?:string[],context?:{notePath,ref?,selection?},clientId?,model?,effort?}`이다. 첨부는 최대 10개이며 업로드 소유자만 새 질문에 첨부한다. 이전 구성원이 제출한 첨부는 권한을 검사한 대화 기록을 통해 서버에서 다시 읽는다. `model`은 `LUNA_MODELS`의 허용 목록이고 미설정 시 `LUNA_MODEL`만 허용한다. `effort`는 `low|medium|high`다. 고정 노트 문맥은 서버가 지정 ref의 정식 원문을 읽으며 selection은 신뢰하지 않는 인용문으로 다룬다.

`GET /luna/models`는 `{models:string[],defaultModel:string,efforts:['low','medium','high'],defaultEffort:string}`을 반환한다. 서버 기본 추론 강도는 요청별 허용 목록보다 넓을 수 있으므로 기본값 선택은 `effort`를 생략한다.

SSE는 `id: <정수 seq>`, `event: <유형>`, `data: <JSON>` 뒤 빈 줄을 보낸다. 이벤트는 `generation {generationId,userMessageId}`, `status {phase}`, `tool {name,state:'start'|'end',summary,path?}`, `citation {path,heading?,anchor?,excerpt?,sha?}`, `delta {text}`, `usage {inputTokens,outputTokens,reasoningTokens}`, `done {message}`, `error {code,message}`다. 도구 요약은 검색어와 노트 경로만 포함하며 노트 본문을 포함하지 않는다. `GET /generations/:id/events`의 `Last-Event-ID`는 해당 생성의 마지막 정수 seq이며 이후 프레임만 재생하고 실시간 프레임으로 이어진다. 완료된 생성도 재생한다.

웹의 `web/lib/chat-stream.ts`는 모든 프레임을 `{id,event,data}` 형태의 `onEvent` 콜백으로 전달한다. 연결이 끊기면 현재 연결에서 처리한 마지막 seq를 `Last-Event-ID`로 전달하며 최대 10초의 지수 백오프로 다시 연결한다. 마지막 seq는 생성 ID별 localStorage에도 저장하지만 새 화면은 저장된 본문과 cursor의 일관성을 보장할 수 없으므로 처음부터 재생해 표시 상태를 다시 구성한다. 새 질문의 최초 연결이 실패하면 같은 `clientId`로 제출을 반복해 중복 질문을 만들지 않는다. 수정·재시도·재생성은 최초 생성 ID를 받기 전까지 멱등성을 보장하지 않으므로 자동 재제출하지 않는다. 생성 ID를 받은 뒤의 재연결은 같은 생성의 이벤트만 읽는다.

HTTP 연결 종료는 생성 작업을 중지하지 않는다. 명시적 `POST /generations/:id/cancel`만 구성원 편집자나 소유자의 생성을 중지한다. 서버 재시작 시 실행 중 작업은 `interrupted`로 전환한다. 실패·취소된 답변도 부분 텍스트와 상태를 저장한다. 공급자 오류는 내부 로그에만 남기며 사용자에게 `generation_failed` 등 안전한 코드와 메시지를 전달한다. 대화에 실행 중 생성은 하나만 허용하며 중복 실행·수정·삭제는 `409 generation_active`다.

스트림 AbortSignal은 관찰만 종료하며 생성 취소를 요청하지 않는다. `cancelGeneration()`만 명시적인 중지 API를 호출한다. 생성 이후의 `error` 프레임은 콜백에 전달한 뒤 Promise를 `null`로 완료하며 `done`은 저장된 메시지로 완료한다. 생성 ID를 받기 전 오류는 콜백 이후 예외로 전달한다.

동일 대화의 동일 `clientId` 제출은 기존 생성 이벤트를 반환하며 질문을 중복 저장하지 않는다. `POST .../messages/:mid/retry`는 실패·취소·중단된 답변이나 남아 있는 사용자 질문을 재시도한다. `POST .../:mid/regenerate`는 assistant 메시지에서 이전 질문의 답변을 새로 만든다. `PATCH .../:mid` 입력은 `{content}`이며 사용자 질문만 수정한다. 이 세 경로는 같은 SSE 형식으로 응답하고 해당 질문 뒤의 턴을 삭제하며 사용자 질문을 새로 추가하지 않는다. 긴 대화는 요청자가 현재 읽을 수 있는 이력에서 오래된 턴을 요청별로 요약하고 최근 턴은 원문으로 유지한다. 요약을 저장하거나 구성원 사이에서 공유하지 않는 이유와 기준은 [Luna](luna.md#엔진이-정의하는-함수-도구)에 기록한다. `010_chat.sql`의 `conversations.summary`와 `summary_through` 열은 기존 DB와 적용된 마이그레이션의 호환성을 위해 남기지만 서비스는 읽거나 쓰지 않는다. 편집·재시도·재생성도 이 열을 초기화하지 않으며 다음 답변에서 현재 남은 이력으로 요약을 다시 만든다. 아직 학습하지 않은 사용자 질문의 `learned_at`은 `NULL`이다.

수정·재생성으로 대화에서 제거한 턴의 생성 이벤트와 `clientId` 기록도 대화가 존재하는 동안 유지한다. 늦게 재전송한 이전 질문은 기존 이벤트를 재생하며 제거한 턴을 복원하지 않는다. 생성 중 요청자가 구성원에서 제거되어도 나머지 구성원에게 완성 메시지를 전달하며, 제거된 사용자의 실시간 스트림은 종료한다. 편집한 사용자 질문은 다시 미학습 상태가 되고 dreaming은 수집한 질문 내용과 현재 내용이 같은 경우에만 학습 완료로 기록한다.

구성원 추가 입력은 `{email,role:'editor'|'viewer'}`이며 조회·추가는 `{members:[{userId,email,name,role}]}`를 반환한다. 삭제는 `204`다. presence 입력은 `{typing}`이며 `{expiresAt}`를 반환한다. 30초 동안 갱신하지 않은 사용자는 제거하며 `conversation.presence {conversationId,users:[{id,name,typing}]}`와 `conversation.updated {conversationId,messageId?}` 이벤트는 구성원 userIds에만 전달한다.

업로드 multipart 필드는 `file`, 선택 필드 `purpose=chat|import`이며 기본값은 `chat`이다. chat은 20 MB 이하 PNG/JPEG/WebP/GIF/PDF/UTF-8 text/Markdown이고 실제 바이트를 검사한다. import는 전역 editor 이상만 생성하며 ZIP을 추가 허용하고 100 MB 한도다. import 목적 파일은 chat 첨부로 사용할 수 없다. 응답은 `{id,userId,name,mediaType,size,createdAt,purpose}`다. 다운로드는 소유자만 가능하며 안전한 Content-Disposition과 탐지한 Content-Type을 반환한다. save 입력은 `{path,baseSha}`이고 경로는 `assets/` 아래이며 공용 NoteWriter를 통해 저장한다. 메시지에서 참조하지 않고 assets로 저장하지 않은 업로드는 `UPLOAD_RETENTION_DAYS`(기본 7일) 이후 제거한다.

proposal 입력은 `{mode:'new'|'edit',path?}`이며 edit에는 경로가 필요하다. 완성된 assistant 답변을 기반으로 `{path,baseSha,original:string|null,proposed}` 전체 노트 초안을 반환한다. 이 호출은 커밋이나 노트 쓰기를 수행하지 않는다. 클라이언트가 diff를 확인한 뒤 별도의 노트 쓰기 접점으로 적용한다.

### 폴더별 접근 제어

관리 화면의 `접근 권한` 탭은 접두사별 규칙 목록, 트리 기반 폴더 선택과 정확한 파일 경로 입력, 사용자·역할·전체 주체 선택과 `none`·`read`·`write` 선택을 제공한다. 같은 주체의 규칙을 저장하면 갱신하고 삭제는 확인을 요구한다. `접근 확인`에서 사용자와 경로를 골라 실효 권한과 적용 규칙을 확인한다. 조회 실패는 빈 규칙 목록과 구분하며 다시 시도할 수 있다.

위키 목록·검색·이력·그래프·첨부 원문과 내보내기는 읽을 수 있는 경로만 반환한다. 읽지 못하는 노트를 직접 열면 없는 노트와 같은 404를 표시한다. 저장·이동·삭제·초안과 첨부 저장은 전역 역할 외에 대상 경로의 쓰기 권한도 요구한다.

공유 대화의 구성원 권한은 노트 읽기 권한을 승격하지 않는다. 각 구성원에게 읽을 수 있는 인용만 표시하고 제한된 인용·고정 문맥을 사용한 턴은 본문과 문맥도 보수적으로 가린다. 생성 이벤트와 후속 Luna 문맥도 같은 제한을 따르며 자세한 결정과 자유 입력의 한계는 [폴더별 접근 제어](access-control.md)에 기록한다.
