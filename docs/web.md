# 웹 버전
웹은 지식 저장소의 위키 탐색·읽기와 근거를 제시하는 질의응답, [선제적 기록과 명시적인 대화 기록 요청](agent.md#대화-중-지식-기록-도구)을 제공한다.

## 배경

사용자는 MCP 클라이언트 없이도 브라우저에서 지식을 읽고 바로 질문할 수 있어야 한다. 웹은 같은 지식 저장소를 사람이 직접 탐색하거나 질문으로 활용하는 접점이다.

## 내용

### 위키 탐색과 읽기

웹에서 위키를 탐색하고 노트를 읽는다. 지식 저장소의 노트와 진입점 색인 구조는 [지식 저장소](knowledge-repository.md)를 따른다. 예를 들어 사용자는 직접 관련 노트를 찾아 읽거나, 아래 질의응답을 통해 질문에 필요한 지식을 찾는다.

### 질의응답

사용자는 웹에서 지식에 대한 질문을 입력한다. 도니는 에이전트형 RAG를 사용해 답변하고 근거 노트를 인용한다. 검색과 노트 읽기를 반복하는 동작은 [RAG](rag.md)에, 메모리 파일의 문맥 주입 규칙은 [지식 저장소](knowledge-repository.md)에 기록한다. 인용은 사용자가 답변의 근거 노트로 돌아가 내용을 확인할 수 있도록 하기 위한 것이다.

도니의 대화 답변은 [대화 문체 지침](agent.md#대화-답변과-문서의-문체)에 따라 친절하고 부드러운 존댓말로 제공한다. 권한 부족 안내도 가능한 다음 행동을 정중하게 설명한다. 위키 노트·일기·노트 초안의 평서형 문체는 바꾸지 않는다.

전역 편집자·관리자의 대화에서는 도니가 [지식 기록 정책](agent.md#대화-중-지식-기록-도구)에 따라 지식을 선제적으로 기록 요청하며, 사용자가 사실의 기록·추가나 기존 내용의 정정을 명시적으로 요청할 수도 있다. 기록은 비동기 쓰기 작업으로 제출하며 초안 검토 창을 거치지 않는다. 도구 제공의 전역 역할·REST 토큰·경로 권한 경계는 [접근 제어](access-control.md#읽기와-쓰기-범위)를 따른다. 조회자에게는 읽기 질의응답만 제공한다.

기록을 요청한 대화에서 도니는 [작업 상태 조회·대기 도구](agent.md#대화-중-지식-기록-도구)로 실제 작업 결과를 확인한 뒤 안내할 수 있다. 답변이 먼저 끝나더라도 쓰기 작업은 계속되며, 진행 중 안내의 작업 링크에서 후속 상태와 결과를 확인한다.

### 대화 기록과 학습

웹 질의응답 대화 기록은 DB에 저장하며 기본적으로 생성자만 접근한다. 소유자가 편집자나 조회자를 초대하면 해당 대화 구성원에게만 공유한다. 관리자라도 구성원이 아니면 대화와 생성 작업에 접근하지 못한다.

대화의 학습 대상과 선제적·명시적 지식 기록 기준은 [도니의 기록 정책](agent.md#대화-중-지식-기록-도구)을 따른다. 두 종류의 기록 요청 모두 [대화에서 제출하는 쓰기](write-flow.md#대화에서-제출하는-쓰기)로 접수하며 야간 배치를 기다리지 않는다. 이와 별개로 [꿈꾸기](dreaming.md#실행-시각과-입력)는 미학습 사용자 발언을 배치로 처리한다. 두 경로의 학습 표시와 중복 처리 관계도 도니의 기록 정책에 설명한다.

두 경로로 반영한 지식은 저장된 경로의 [접근 규칙](access-control.md)을 따른다. 사용자 권한으로 실행하는 기록 작업과 달리 꿈꾸기는 시스템 권한을 사용하며, ACL 경계 간 정보 이동의 한계는 [꿈꾸기와 한계](access-control.md#꿈꾸기와-한계)에 기록한다.

### 변경 이력

`/history`의 기본 화면은 커밋·쓰기 작업·꿈꾸기·원격 백업을 날짜별로 묶은 타임라인이다. 성공한 쓰기 작업과 대응하는 커밋은 카드 하나로 합친다. 노트 칩은 해당 노트의 변경 이력으로 이동하고 `노트 열기`는 본문으로 이동한다. 유형·출처·경로 필터를 URL에 유지하며 필터가 있으면 `필터 초기화`를 표시한다. 타임라인에서 경로를 필터링할 때는 `/history?view=activity&path=`를 사용한다. 불투명 `before` 커서로 이전 항목을 자동 또는 버튼으로 더 읽는다. 공통 `main.updated`·`job.updated`·`dream.updated` 신호가 새 항목을 맨 위에 반영하며 새로 들어온 항목을 강조한다.

이력의 원천은 지식 저장소의 git 커밋과 DB의 쓰기 작업 기록이다. 커밋의 요청자·수행자 기록 규칙은 [쓰기 흐름](write-flow.md#요청자-추적과-실패-복구)을 따른다. 잘못된 지식을 직접 고치거나 역변경하는 절차는 [직접 편집](write-flow.md#직접-편집과-낙관적-동시성-제어)과 [되돌리기](write-flow.md#이력-조회와-되돌리기)에 설명한다.

#### 노트별 이력과 비교

`/history?path=`는 `follow=1`로 이름 변경 이전의 커밋까지 읽으며 당시 경로와 이름 변경을 날짜별 이력에 표시한다. 기본 작성 정보는 대표 이름·출처·상대 날짜로 구성하며 이메일이나 SHA를 앞세우지 않는다. `변경 내용 보기`를 누르면 해당 행의 diff를 불러와 펼친다. `이 버전 보기`는 당시 경로의 `/wiki/<path>?ref=<sha>`로 이동하며 이름 변경 전 버전에는 `&current=<현재 경로>`를 붙인다. 과거 버전 읽기 화면의 안내 배너는 이 현재 경로를 복원 대상으로 사용한다. `현재와 비교`는 선택한 과거 버전과 현재 버전을 비교한다.

`이 버전으로 복원…`은 선택한 버전의 본문을 현재 대상 노트에 그대로 적용하는 동작이다. 복원 대화상자는 과거 버전과 적용할 현재 노트를 구분하고 변경 내용을 미리 보여 준다. `stale_note`가 발생하면 최신 내용을 다시 조회하며 새 diff를 확인하는 체크박스를 선택해야 다시 적용할 수 있다. 성공 뒤에는 `복원된 노트 열기`와 `변경 기록 보기`를 제공한다.

체크박스로 두 버전을 골라 `/history/compare?base=&head=&path=`를 연다. 비교 화면은 이력에서 버전을 고르는 선택기를 기본으로 제공하며 선택한 값을 유지하고 두 버전을 맞바꾸거나 `현재 버전`을 고를 수 있다. 접힌 `고급 비교`를 열면 SHA·git ref를 직접 입력할 수 있으며 기존 `base`·`head`·`path` URL도 사용할 수 있다. 이전 커밋은 마지막 SHA를 `before`로 더 읽는다. 이름 변경 전후의 버전도 비교할 수 있다.

커밋 상세 `/history/commits/[sha]`는 변경 파일과 diff를 기술 정보보다 먼저 보여 주며 연결된 작업으로 이동할 수 있다. 병합 커밋의 부모 번호와 SHA를 선택할 수 있고 존재하지 않는 커밋에는 찾을 수 없다는 안내를 표시한다. 데스크톱 노트 이력과 커밋 상세에서 작성자·요청자·커미터, 커밋 trailer, SHA와 절대 시각 같은 상세 메타데이터는 접힌 `기술 정보`에서 확인한다.

노트 이력의 더 보기 메뉴와 커밋 상세의 `이 변경만 취소…`는 특정 버전의 본문을 그대로 복원하는 대신 선택한 커밋의 역변경을 적용한다. 편집자 이상은 커밋 전체 또는 선택한 파일의 역변경을 미리 본 뒤 적용한다. 병합 커밋은 첫 번째 부모 기준이며 다른 부모를 보는 중에는 선택 파일의 취소를 막는다. 성공 뒤에도 대화상자에 머무르며 노트 링크와 `작업 상세`를 제공하고 작업 화면으로 강제 이동하지 않는다.

공유 `DiffView`는 화면 너비가 768px 미만이면 저장된 데스크톱 설정과 관계없이 통합 모드로 시작한다. 768px 이상에서는 저장된 모드를 사용하며 저장값이 없으면 나란히 모드로 시작한다. 사용자가 현재 세션에서 직접 고른 모드는 이 기본값보다 우선한다. 복원과 취소 미리보기는 현재 내용과 복원 또는 취소 결과를 구분해 표시한다. 줄 번호·단어 단위 강조·접힌 미변경 영역·다중 파일 이동을 제공하며 미변경 영역은 patch 또는 전체 본문에 실제로 포함된 문맥만 펼친다. 바이너리와 이름만 변경된 파일은 텍스트 diff가 없음을 표시하고 큰 patch는 명시적으로 불러온다.

`/history/blame?path=&ref=`와 노트의 Blame 모드는 같은 `BlameView`를 사용한다. 일반 노트의 속성·목차·article과 분리된 높이를 채우는 뷰포트 안에서 가로·세로로 스크롤한다. 데스크톱은 줄 옆 gutter에 작성 정보를 표시하고 연속된 같은 커밋의 범위 메타데이터를 세로 스크롤 중 고정한다. 모바일은 고정 폭 작성 정보 gutter 대신 커밋별 그룹 헤더와 `작성 정보` 버튼을 제공한다.

작성 정보에는 SHA·작성자·상대 날짜와 나이 색상 바를 표시한다. 데스크톱의 hover·키보드 초점이나 모바일의 `작성 정보` 버튼으로 제목·날짜·출처·커밋·작업 링크를 연다. 정보창은 `document.body` portal에 표시해 스크롤 영역에 잘리지 않으며 Escape·스크롤·resize로 닫힌다. 현재 본문 조회는 `['notes/content',path]`, 과거 본문 조회는 `['notes/content',path,ref]` 캐시를 공유한다.

#### 쓰기 작업과 꿈꾸기·일기

`/jobs`는 `mine=1`로 자신의 작업을 조회하고 상태와 `before` 작업 ID를 URL에 유지한다. 서버가 상태 필터를 제공하지 않으므로 원본 페이지를 순회하여 오래된 일치 작업도 찾는다. `/jobs/[id]`는 저장된 단계 이벤트로 대기·준비·편집·커밋·병합·필요 시 충돌 해결·색인·정리·완료 또는 실패를 표시한다. 공통 `job.updated`로 갱신하며 주기적으로 폴링하지 않는다. 충돌 경로와 실제 이벤트만 표시하고 기록에 없는 해결 결과를 만들지 않는다. 편집자 이상인 소유자 또는 관리자는 실패 작업을 새 ID의 작업으로 재시도하고 대기 작업만 확인 후 취소한다.

서브에이전트 이벤트가 있는 작업 상세에는 `서브에이전트` 목록을 표시한다. 같은 ID의 마지막 이벤트를 기준으로 이름·진행 중/완료/실패/취소 배지·담당 파일·도구 호출 수·결과 요약 또는 오류를 보여 준다. 이 목록도 기존 `job.updated` 갱신을 사용하며 서브에이전트가 없는 작업에서는 숨긴다.

`/dreams`는 실행 ID 커서로 기록을 더 읽고 `/dreams/[id]`는 입력 커밋 범위·요약·변경 파일·일기·최종 merge SHA·소요 시간·오류·push 결과를 표시한다. 이력 패널과 타임라인의 백업 배지는 마지막 성공한 원격 push의 경과 시간, 로컬 전용 건너뜀과 실패를 구분한다. 이 표시와 전체 백업의 경계는 [운영](operations.md#웹-운영-화면과-지금-실행)을 따른다.

`/journal?date=YYYY-MM-DD`는 한국 날짜 기준 일기를 달력과 월별 목록으로 찾아 공유 Markdown 렌더러로 읽는다. 이전·다음 버튼은 일기가 있는 날만 건너뛰지 않고 실제 하루씩 이동한다. 일기 없는 날짜와 조회 실패를 구분하며 해당 날짜의 꿈꾸기와 노트 커밋으로 이동한다.

이력 사이드바의 제목은 `최근 변경`이며 현재 노트의 최근 10개 이력과 타임라인·작업·꿈꾸기·일기 링크를 실시간으로 제공한다. 이력 화면에서는 URL의 `path`를 따라 해당 노트의 이력을 표시한다. Ctrl/⌘ K 또는 Ctrl/⌘ Shift P의 명령 팔레트는 `이력 패널 열기`·`이 노트의 변경 이력`·`줄별 작성자 보기`·`전체 변경 활동`을 서로 다른 동작으로 제공하며 일기와 꿈꾸기 기록도 열 수 있다. `줄별 작성자 보기`는 이력 화면에서도 현재 경로의 작성자 화면을 연다.

### 로그인과 관리 화면

로그인 뒤 개인 설정과 관리 기능은 `/settings?tab=<id>` 하나에서 제공한다. 사용자·권한 정책과 첫 관리자 등록 절차는 [인증과 권한](auth.md)을 따른다.

#### 통합 설정

개인 탭은 `account`(계정), `appearance`(화면 테마), `tokens`(API 토큰), `mcp`(MCP·Skill), `export`(내보내기)다. 관리자에게만 `ops`(운영 현황), `users`(사용자), `login`(로그인 설정), `acl`(접근 권한), `audit`(감사 로그)를 추가로 표시한다. bare `/settings`와 알 수 없는 탭은 계정 탭을 표시한다. 탭을 바꾸면 `router.replace`와 `scroll:false`로 URL을 동기화하므로 새 브라우저 이력 항목을 만들지 않는다.

한 번에 `tabpanel` 하나만 렌더링한다. 창 너비가 아니라 `settings-layout` 컨테이너의 너비가 720px 이상이면 개인·관리 그룹을 나눈 세로 tablist를 쓰고, 그보다 좁으면 가로로 스크롤하는 tablist를 쓴다. 넓은 화면이라도 양쪽 사이드바로 본문이 좁아지면 가로 목록이 된다. ResizeObserver가 같은 기준으로 ARIA orientation과 방향키를 동기화한다. 세로 목록은 위·아래 방향키, 가로 목록은 왼쪽·오른쪽 방향키로 순환하고 Home·End로 처음·마지막 탭을 선택한다. 선택한 탭만 Tab 초점을 받으며 탭과 패널을 ARIA 속성으로 연결한다. 비관리자가 관리 탭 URL을 직접 열면 권한이 필요하다는 빈 상태만 표시하고 관리 패널과 조회 훅은 마운트하지 않는다.

내용의 `settings-panel` 컨테이너도 자신의 너비를 기준으로 배치한다. 기본 폼은 672px 이상에서 두 열, 사용자 추가 폼은 896px 이상에서 세 열, 운영 지표는 1024px 이상에서 네 열로 확장한다. 사용자·ACL 표의 최소 너비는 600px, 감사 표는 720px이고 헤더는 줄바꿈하지 않는다. 좁은 패널에서는 표 영역 안에서만 가로 스크롤하며 설정 화면 전체를 늘리지 않는다.

이전 `/admin`과 `/admin?tab=overview`는 `/settings?tab=ops`로 이동한다. 이전 `users`, `audit`, `acl`, `export` 탭은 같은 이름의 설정 탭으로, `settings`는 `login`으로 이동한다. `/settings?section=tokens|export`도 대응하는 `tab` URL로 전환한다. 이는 이전 링크를 위한 서버 redirect이며 이전 관리 화면과 anchor 내비게이션은 더 이상 사용하지 않는다.

`users`와 `login`은 사용자 추가·역할 변경·삭제, 등록 이메일 제한·허용 도메인 폼을 재사용한다. 마지막 관리자 보호 등 서버 오류를 화면에 표시한다. `audit`에서는 숫자 행위자 ID와 정확한 행위 문자열을 조합해 필터링하고 커서로 이전 기록을 더 읽는다. 감사 기록의 범위와 비밀값 제외는 [인증과 권한](auth.md#감사-기록)에 기록한다. 운영 상태와 지금 실행 동작은 [운영 화면과 실행](operations.md#웹-운영-화면과-지금-실행)을 따른다.

#### API 토큰과 연결 안내

`tokens`에서 자신의 API 토큰을 관리하며 관리자는 전체 토큰 보기로 `all=1` 목록을 조회한다. 토큰 발급은 쿠키 로그인 세션에서만 가능하고 이름·독립적인 read/write 범위·선택적 미래 만료 시각을 입력한다. 비밀값은 발급 직후 한 번만 표시하며 복사·보관 후 명시적으로 지운다. 캐시나 브라우저 저장소에 비밀값을 보관하지 않으며 다시 조회할 수 없다. 폐기는 확인 뒤 적용한다. 토큰의 권한과 MCP OAuth와의 구분은 [인증과 권한](auth.md)을 따른다. `mcp` 탭의 클라이언트별 연결·발견 검사·문제 해결은 [설치형 Skills의 MCP 연결 안내](skills.md#별도-mcp-연결과-oauth)를 따른다.

#### 원문 가져오기와 내보내기

`/imports`는 자신의 가져오기 목록을 제공하며 관리자는 전체 목록을 확인한다. 편집자 이상은 URL·텍스트·PDF/Markdown/텍스트 파일·Obsidian vault ZIP·Notion export ZIP을 추가한다. `/imports?new=1`로 들어오면 가져오기 창을 자동으로 연다. 닫거나 생성에 성공하면 `new`만 제거하고 다른 쿼리와 스크롤을 유지한다. URL을 읽는 컴포넌트는 Suspense 안에 둔다. 파일 업로드·원문 크기 한도와 보안 거절 사유는 [원문 수집](ingestion.md)을 따른다.

목록과 상세 서랍은 추출·대기·실행·완료·실패·취소 상태를 표시하며 연결된 `job.updated` 이벤트로 갱신한다. 상세에서 불변 raw 경로·쓰기 작업·오류를 확인한다. raw의 바이너리 경로는 기록 그대로 유지하며 해당 경로를 노트 링크로 열었을 때 Markdown 본문이 없는 파일은 노트 조회 오류가 될 수 있다. 이전 목록은 마지막 import ID를 커서로 더 읽는다. 서랍은 Escape로 닫고 원래 요소로 초점을 복원한다.

`/settings?tab=export`의 단일 내보내기 패널은 노트 트리 또는 직접 입력한 경로 접두사로 현재 커밋된 main을 ZIP으로 다운로드한다. ZIP에는 `manifest.json`이 포함된다. Git bundle은 전체 main 이력을 다운로드하며 부분 경로와 함께 선택할 수 없다. 지식 파일 내보내기는 대화·사용자 DB·임시 업로드의 전체 백업이 아니다. 명령 팔레트에서도 같은 설정 탭으로 이동한다.

#### 레이아웃·간격·색상 규칙

헤더 높이는 44px, 상태 표시줄은 24px이다. `/wiki`와 `/graph` 본문은 같은 작업 공간을 사용하며 셸의 외곽 패딩 없이 편집기 그룹의 높이를 채운다. 다른 경로는 셸이 `px-5 py-4`와 `max-w-6xl` 본문 래퍼를 제공하므로 개별 페이지가 외곽 패딩과 최대 너비를 다시 지정하지 않는다.

설정·작업·이력·운영·검색·대화 같은 비위키 화면도 VS Code의 설정 편집기나 소스 제어 뷰처럼 평평하고 조밀하게 그린다. 이전에는 화면마다 `rounded-lg border bg-card p-4` 카드를 쌓았는데, 넓은 안쪽 여백과 카드 경계가 작업 공간 셸의 밀도와 어긋나 일반 SaaS 대시보드처럼 보였기 때문이다. 둥근 모서리 토큰도 VS Code에 맞춰 작게 둔다(`rounded-sm` 2px, `rounded-md` 3px, `rounded-lg` 4px, `rounded-xl` 6px).

| 요소 | 규칙 |
| --- | --- |
| 페이지 섹션 간격 | `space-y-4`다. `PageHeader`는 16px 제목·12px 설명과 `border-b pb-2`를 가진 제목 표시줄이며 하단 여백은 두지 않는다. |
| 섹션 | 테두리·배경·안쪽 여백 없이 `space-y-2`로 쌓는다. 제목 행은 `flex h-7 items-center gap-1.5 border-b text-label-13 font-semibold`이다. |
| 목록 | 섹션 제목 바로 아래에는 위쪽 테두리 없이 `divide-y border-b`를 쓰고, 제목 없는 목록은 `divide-y border-y`를 유지한다. 카드 배경과 좌우 테두리를 두지 않는다. 행은 `px-2 py-1.5`, 본문 13px(`text-label-13`), 메타데이터 `text-xs`이고 정보는 두 줄 이내로 모은다. |
| 키·값 묶음 | 상자 없이 `grid gap-x-6 gap-y-1.5`로 두고 레이블은 `text-xs text-muted-foreground`다. 개수 같은 수치도 `text-sm font-semibold tabular-nums`로 크게 키우지 않는다. |
| 필터 막대 | 상자 대신 `flex flex-wrap items-end gap-2 border-b pb-2` 도구 막대로 둔다. |
| 알림 상자 | 의미 색의 옅은 배경과 테두리를 유지하고 안쪽 여백은 `px-3 py-2`다. |
| 테두리가 필요한 면 | 코드·diff·blame·그래프 캔버스·표·스크롤 영역·입력창만 얇은 테두리를 유지하고 안쪽 여백은 `p-2`~`p-3`이다. |
| 리사이즈 경계 | 인접한 리사이즈 `Separator`가 유일한 경계를 제공하므로 패널은 맞닿은 면에 테두리를 중복해서 두지 않는다. `Separator`가 없으면 필요한 테두리를 유지한다. 넓은 포인터 조작 영역과 키보드 리사이즈는 유지한다. |
| 대화 상자 | `p-4`와 `shadow-lg`를 기준으로 한다. |
| 빈 상태·로딩 | 점선 카드 없이 `py-6`의 작은 안내문과 `py-3`의 로딩 행으로 표시한다. |

사이드바 헤더는 36px(`h-9`)·좌우 12px(`px-3`), 본문은 `min-h-0 flex-1 overflow-auto px-2`로 독립 스크롤한다. 탐색기 행은 높이 28px·글꼴 13px이다. Button 기본·sm·icon-sm과 필터는 32px, lg·icon-lg와 기본 Input·NativeSelect 및 비교·경로 변경 폼은 36px이며 Textarea 최소 높이도 36px이다.

중립색·얇은 테두리와 LINE Seed Sans KR·Geist Mono 글꼴을 유지한다. 컴포넌트의 색상은 `background`, `foreground`, `card`, `muted`, `border`, `ring`, `success`, `warning`, `destructive` 같은 의미 토큰을 사용한다. raw 팔레트 utility나 임의의 밝은/어두운 색을 화면마다 지정하지 않고 실제 색 정의는 공통 CSS 테마에 둔다. `--popover`는 `--card`, `--popover-foreground`는 `--foreground`를 참조하므로 정보창도 테마에 맞는 불투명 표면을 가진다. diff·코드·수식·callout·그래프의 구체적인 테마 갱신은 [읽기 성능](performance.md#프런트엔드-읽기-비용)을 따른다.

작업 단계 행은 `relative` containing block을 둔다. 절대 위치의 `sr-only` 안내가 main 스크롤 영역 밖으로 나가 두 번째 루트 스크롤바를 만드는 문제를 막기 위한 것이다.

#### 공통 알림

저장·갱신·이미지 첨부·파일 작업·복사·운영 실행 결과는 `notify({title,description?,tone?,action?})`로 알린다. `Notifications`는 셸에 한 번만 마운트하고 최대 네 개를 표시한다. 기본 info와 success는 5초 뒤 닫히고 error는 사용자가 닫을 때까지 남는다. 선택적인 action은 노트·작업·실행 기록 등 결과 링크를 제공한다. `aria-live="polite"`와 status/alert 역할로 보조 기술에도 전달한다.

### 구현된 웹 화면

`web/`는 별도 패키지가 아닌 단일 루트 패키지 안의 Next 프로젝트 디렉터리다. UI 의존성은 루트에서 설치하며 `pnpm exec next build web`로 `web/.next`에 빌드한다. 평소 개발과 실행은 Nest와 Next를 한 프로세스로 묶는 루트 스크립트를 사용하며 명령은 [개발 환경](development.md)에 기록한다. 클라이언트 화면은 같은 origin의 `/api`와 `/auth`를 사용하므로 별도 개발 프록시가 필요하지 않다.

화면은 React 19, Next.js App Router, TanStack Query, Tailwind CSS 4로 구성한다. `web/app`은 라우트와 레이아웃, `web/pages-ui`는 클라이언트 화면, `web/components`와 `web/lib`는 공통 UI와 API·스트림 처리를 담당한다. 최상위 레이아웃에 서버 상태 캐시와 테마 제공자를 두고 콘솔 레이아웃에서 로그인을 확인한다.

작업 공간은 헤더, 왼쪽 활동 표시줄과 크기를 조절하는 기본 사이드바, 탭과 분할 가능한 편집기 그룹, 오른쪽 도니 패널, 하단 상태 표시줄 순서다. 활동 표시줄은 탐색기·검색·백링크·태그·이력을 제공하고 관리자에게만 운영 패널을 추가한다. 아래에 고정된 톱니바퀴와 사용자 메뉴의 설정은 `/settings`를 연다. 도니는 왼쪽 패널 목록에 넣지 않으며 헤더 버튼으로 오른쪽 보조 사이드바를 연다. 헤더에는 테마 선택 메뉴와 계정·역할·로그아웃 메뉴도 있다. 모바일 기본 사이드바는 본문을 대체하지 않는 모달 서랍이며 Escape로 닫고 원래 버튼으로 초점을 돌려준다.

`/api/me`가 401을 반환하면 Google 로그인 화면을 표시한다. `/login`에서도 같은 로그인 화면을 직접 열 수 있다. 로그인 버튼은 `/auth/google/login`으로 이동하며, 로그인 후 돌아갈 앱 경로를 `next`에 전달한다. 다른 API에서 세션 만료를 받으면 캐시를 지우고 로그인 화면으로 전환한다.

노트 경로는 `/wiki/[...path]`로 유지하며 각 경로 조각을 URL 인코딩한다. `/wiki`로 들어오면 `index.md`를 우선 선택한다. 파일 트리는 노트 본문과 분리된 탐색기 패널에 있어 노트를 바꾸어도 상태를 유지한다. 노트의 폴더 경로는 클릭 가능한 breadcrumb로 표시하며 폴더를 누르면 탐색기에서 해당 위치를 드러낸다. 마지막 경로 조각에는 frontmatter 제목을 표시하고 hover `title`로 전체 파일 경로를 보여 준다. 노트 헤더에서 즐겨찾기와 해당 경로의 변경 이력을 열 수 있다.

노트 헤더는 breadcrumb와 아이콘 동작 한 줄, `text-lg` 제목과 작은 저장 상태 한 줄로 조밀하게 둔다. 즐겨찾기·변경 이력·줄별 작성자·이 노트에 대해 묻기는 `icon-xs`(24px) 버튼이며 접근 가능한 이름과 `title`을 유지한다. 편집자의 더보기 메뉴는 원문 편집과 라이브 편집을 전환한다. 제목 옆 점은 저장하지 않은 변경을 뜻하고 저장 중·저장됨·저장 실패와 다시 시도·충돌을 표시한다. 별도 모드 그룹, 커밋 메시지 입력, 저장·버리기 버튼은 두지 않아 분할된 편집기 그룹에서도 본문 높이를 확보한다.

현재 Next.js 16의 클라이언트 경로 이동에서 동적 경로 매개변수는 URL 인코딩된 값으로 전달된다. 노트의 각 경로 조각과 대화·작업·커밋 식별자는 화면에서 한 번만 디코딩한 뒤 API에 넘긴다. API 클라이언트가 요청 경로를 다시 인코딩하므로 이 처리를 생략하면 한글 노트 경로가 이중 인코딩되며, 두 번 디코딩하면 파일명에 들어간 `%20` 같은 문자열이 달라진다.

검색 화면의 검색어·필터·소제목 연결과 검색·백링크·태그 패널의 동작은 [검색과 지식 탐색](#검색과-지식-탐색)을 따른다. 도니 화면의 대화 목록·실시간 답변·문맥·첨부·초안 적용은 [도니 대화 작업 공간](#도니-대화-작업-공간)을 따른다.

변경 이력 화면과 노트별 비교·되돌리기·Blame, 쓰기 작업 단계, 꿈꾸기 보고서와 일기 탐색의 경로와 동작은 [변경 이력](#변경-이력)을 따른다. 관리 기능의 경로와 접근 제한은 [통합 설정](#통합-설정)을 따른다.

### 도니 대화 작업 공간

`ChatPane({variant:'panel'|'page',conversationId?,onClose?})`는 공통 대화 모듈이다. `/chat`와 `/chat/[id]`는 URL 매개변수만 전달하는 page 변형을 사용하며 `?new=1`은 새 대화, `?search=1`은 기록 검색을 연다. 오른쪽 panel 변형은 스레드 ID를 내부 상태로 관리하므로 기록 선택·새 대화 생성은 현재 위키 URL을 바꾸지 않는다. `편집기 영역 열기`만 `/chat/<id>`로 이동한다. 마지막 스레드는 계정별 `llmwiki.chat.last-thread.<userId>`에 저장해 패널을 다시 열 때 복원한다.

`CHAT_OPEN_EVENT`의 `conversationId`, `newThread`, `focusSearch` 요청은 셸이 표시 위치를 결정한다. 768px 이상이며 `/chat` 이외의 경로이면 오른쪽 패널을 펼치고 초점을 옮긴다. 767px 이하 또는 `/chat` 경로에서는 `/chat/<encodedId>`, `/chat?new=1`, `/chat?search=1`, `/chat` 중 해당 URL로 이동한다. 이때 panel 리스너는 요청을 처리하지 않아 같은 대화를 두 번 생성하지 않는다. 패널을 접어도 마운트 상태는 유지해 진행 중 관찰과 초안을 보존하지만 `/chat` 경로에서는 패널을 렌더링하지 않는다.

pane 안의 기록은 구성원 대화를 최근 활동 순으로 표시한다. 제목·메시지 검색은 API의 `q`를 사용하며 결과에 최대 240자의 본문 조각을 표시한다. 소유자와 편집자는 제목을 바꾸고 Enter로 저장하거나 Escape로 취소한다. 소유자만 확인 후 삭제하며 구성원이 둘 이상이면 공유 배지를 표시한다. 실시간 조회 갱신은 [공통 이벤트 계약](events.md)의 중앙 무효화를 사용한다.

답변은 `generation`·`status`·`tool`·`citation`·`delta`·`usage`·`done`·`error`를 모두 읽는다. status·tool·citation으로 작업 단계 타임라인을 만들고 검색어·읽은 노트 경로를 표시한다. `write_knowledge` 단계는 `지식 기록 요청`으로 표시하며 성공한 종료 이벤트의 `jobId`가 있으면 `/jobs/<id>`의 `작업 보기` 링크를 제공한다. 이 단계의 종료 체크는 요청 접수를 뜻하며 저장 완료를 뜻하지 않는다. `get_write_status`는 `기록 상태 확인`, `wait_write`는 `기록 완료 대기`로 표시하며 두 도구의 시작·종료 이벤트에 담긴 `jobId`에도 같은 작업 링크를 제공한다. 진행 중 단계에는 spinner, 끝난 단계에는 체크를 표시하며 답변 종료 시 `n단계 · 노트 k개 참고` 요약으로 자동 접는다. 상세 단계와 작업 링크는 클라이언트 상태이므로 완료 답변을 새로 불러오면 저장된 인용 수만 요약하고 상세 기록을 복원하지 않는다. 실행 중 답변은 연결된 `generationId`로 전체 이벤트를 재생한 뒤 실시간 생성에 이어 붙이며 작업 링크도 재구성한다. 네트워크가 끊기면 마지막 이벤트 이후부터 자동 재연결한다. 화면 이동은 생성 관찰만 종료하며 중지 버튼과 Escape만 서버 생성 취소를 요청한다. 생성 ID 도착 전의 중지도 ID 수신 직후 적용한다.

사용자 질문은 오른쪽 말풍선이며 도니의 답변은 아바타·이름을 가진 전체 너비 본문이다. 메시지는 위키와 같은 Markdown 렌더러를 사용한다. 인용 칩에는 소제목과 본문 미리보기를 제공하고 현재 SHA와 다르면 변경됨 표시와 `?ref=` 과거 노트 링크를 사용한다. 모델·추론 강도·입력·출력·추론 토큰과 스트리밍 커서를 표시한다. hover 또는 키보드 focus로 복사·수정·재생성·새 노트 저장·기존 노트 적용을 연다. 실패·취소·서버 중단은 부분 답변과 인라인 재시도로 표시한다. 질문 수정과 답변 재생성은 이후 대화가 교체된다는 확인을 요구한다.

메시지는 독립 영역에서 스크롤하고 composer는 하단에 고정한다. 위로 스크롤하면 자동 추적을 멈추며 `최근 메시지로` 버튼으로 돌아온다. 입력 textarea는 내용과 pane 너비에 따라 80–240px로 자동 확장한다. Enter는 전송, Shift+Enter는 줄바꿈이며 IME 조합 중 Enter는 전송하지 않는다. 비어 있는 입력의 위쪽 화살표는 마지막 질문 수정을 연다.

paperclip 버튼·pane 전체 끌어 놓기·클립보드 이미지 붙여넣기로 첨부를 추가한다. 드롭 중에는 pane 전체 오버레이를 표시한다. 전송 전 썸네일·파일 카드·진행률·오류·제거를 제공하고 보낸 첨부도 썸네일과 카드를 유지한다. 이미지는 확대 창으로 열고 파일은 다운로드 링크로 표시한다. 업로드 한도·허용 형식·소유자 다운로드 규칙은 [첨부 API](#rest-api와-저장-규칙)를 따른다.

파일 전달은 전역 이벤트 대신 pane별 `ChatComposer`의 `files?:{key:number,files:File[]}`를 사용한다. `prompt?:{key:number,content:string,context?}`는 예제 질문과 노트 문맥을 초안으로 전달한다. 배치마다 새 key를 주고 같은 key는 다시 처리하지 않는다. disabled·streaming·edit·submitting 중 들어온 파일 배치는 무시하며 나중에 재생하지 않는다. 빈 대화는 예제 질문 세 개를 제공하고 활성 노트가 있으면 현재 노트 질문을 추가한다. 예제는 초안과 노트 문맥만 채우며 자동 전송하지 않는다. 현재 노트의 메타데이터까지 읽어 둔 경우에만 해당 `updatedSha`도 문맥에 고정한다.

노트 또는 선택한 문장으로 도니에게 질문하려면 `askAgent({notePath,ref?,selection?})`를 호출해 새 대화를 열고 제거 가능한 고정 문맥을 전달한다. `@` 추천이나 `/note <path>`도 노트를 고정한다. 고정 문맥은 브라우저 세션의 대화별 상태로 유지하며 후속 질문에도 전송하고 제거하면 해제한다. `/search <q>`는 현재 대화를 유지하면서 입력 아래 검색 결과와 전체 검색 링크를 표시한다. `/save`는 마지막 완성 답변의 새 노트 초안을 열고 `/help`는 입력 도움말을 표시한다. 모델과 추론 강도 선택은 서버가 제공한 허용 목록만 사용하며 기본값은 요청에서 생략한다.

새 노트 초안은 제안 경로를 수정할 수 있고 기존 노트 적용은 대상 노트를 선택한다. 초안 요청은 저장하지 않는다. 검토 창에서 제안 본문을 편집하고 공통 DiffView의 분할·통합 비교로 변경을 확인한 뒤 반환된 `baseSha`로 `PUT /api/notes`를 실행한다. 409 충돌은 덮어쓰지 않고 최신 원문을 기준으로 초안을 다시 제안하도록 안내한다. 성공 알림은 노트·쓰기 작업·커밋 링크를 제공한다. 첨부의 위키 자산으로 저장은 현재 커밋을 자동 조회해 `assets/` 경로로 저장하며 충돌 시 명시적으로 최신 기준을 다시 읽는다. 위키 쓰기와 자산 저장은 [폴더별 접근 제어](access-control.md)의 대상 경로 쓰기 권한도 요구한다.

공유 창은 구성원을 표시하고 소유자만 등록된 이메일을 편집자·조회자로 추가하거나 역할을 바꾸고 제거한다. 조회자는 대화를 읽지만 질문을 보낼 수 없다. 창에 초점이 있고 해당 pane이 실제 표시될 때만 10초마다 heartbeat를 전송한다. 입력 상태는 같은 `data-chat-pane`의 composer에서만 읽어 숨겨진 패널과 page 대화가 서로 덮어쓰지 않는다. 다른 구성원의 아바타와 입력 상태를 실시간으로 표시하며 초점 상실·화면 종료·pane 숨김 뒤 갱신을 멈춘다. 서버의 접속 TTL은 [대화 API](#rest-api와-저장-규칙)를 따른다.

팔레트의 새 대화·대화 검색·현재 노트로 대화 시작은 각각 새 스레드, 기록 검색, 현재 노트와 읽은 SHA를 고정한 새 대화를 연다. 키 조합은 [단축키와 테마](#단축키와-테마)의 단일 레지스트리를 따른다.

생성 ID가 포함된 서버 응답을 받을 때까지 입력과 첨부를 보존하며 최초 제출이 거절되면 다시 편집하고 전송할 수 있다. 선택한 문맥이 32,000자를 넘으면 전송 전에 길이 오류를 표시하고 원문을 임의로 자르지 않는다. Escape는 열린 확대·공유·검토 창이나 IME 조합을 먼저 처리하며 이때 답변을 취소하지 않는다.

### 작업 공간과 패널

`web/components/workspace/registry.tsx`에 식별자·제목·아이콘·기본 경로·렌더러·관리자 여부를 등록한다. 탐색기·검색·백링크·태그·이력·운영 패널은 이 목록을 공유한다. 도니 패널은 별도 오른쪽 보조 사이드바이며 레지스트리에는 없다. 백링크나 운영 패널을 열어도 현재 노트 경로를 바꾸지 않는다. 운영 패널의 상태·실행 동작은 [운영](operations.md#웹-운영-화면과-지금-실행)을 따른다.

기본 사이드바는 200–480px(기본 280px), 도니 패널은 300–700px(기본 400px)이며 편집기는 최소 260px을 남긴다. 810px 미만의 데스크톱에서 한 사이드바를 열면 다른 쪽을 접는다. 창 크기를 바꾸어도 사이드바의 픽셀 너비를 유지한다. 1px 구분자는 넓은 포인터 표적과 키보드 크기 조절을 제공하며 더블클릭하면 기본 크기로 복원한다. `react-resizable-panels` 4.14.2의 `onLayoutChanged`와 `isUserInteraction`으로 사용자 드래그 완료 때 저장한다. 드래그 콜백에서 다시 resize하지 않고 기본 크기는 고정하며 버튼·화면 전환은 패널 핸들로 처리해 피드백 루프를 피한다. 편집기 분할 트리에서 그룹 하나가 중첩 분할로 바뀌면 새 Panel이 등록되기 전에 `setLayout`을 호출할 때 라이브러리가 `No layout data found` 예외를 던지므로, 자식 구성이 바뀐 분할의 비율은 한 프레임 뒤에 적용한다.

탐색기는 경로와 이미 읽은 노트 제목을 필터링하고 폴더 확장 상태를 유지한다. 선택한 파일의 상위 폴더를 자동으로 펼치고 활성 파일을 표시한다. 목록 조회 오류는 빈 저장소와 구분하고 다시 시도 버튼을 제공한다. 별표로 즐겨찾기를 바꾼다. 최근 노트는 최대 30개를 보관하며 빠른 열기 후보에 쓴다.

탐색기 본문은 VS Code 탐색기처럼 열린 편집기·즐겨찾기·저장소 루트의 세 뷰를 세로로 쌓는다. 각 뷰는 24px 머리글의 화살표로 접고 펼친다. 열린 편집기와 즐겨찾기는 항목이 없으면 뷰 자체를 숨기고 목록 높이를 각각 `min(12rem, 25vh)`, `min(10rem, 20vh)`로 제한해 따로 스크롤한다. 저장소 루트는 남은 높이를 모두 채우며 펼친 상태에서 최소 128px을 유지한다. 이전에는 즐겨찾기·최근 노트·파일 트리가 하나의 스크롤 영역에 이어져 있어서 위쪽 목록이 늘어나면 파일 트리가 아래로 밀려 거의 보이지 않았다. 필터를 입력하는 동안에는 열린 편집기·즐겨찾기를 숨기고 저장소 루트를 접혀 있어도 펼쳐 보인다. 폴더 위치 표시(`workspace-reveal`)도 저장소 루트를 펼친다.

열린 편집기는 탐색기에서 최근 노트 목록을 대신한다. 사용자가 실제로 띄워 둔 화면 조합을 편집기 그룹 단위로 보여 주는 것이 VS Code의 작업 흐름에 맞기 때문이다. 그룹이 둘 이상이면 레이아웃 순서대로 `1 그룹`, `2 그룹` 머리글을 두고 그 아래에 그룹의 탭을 탭 순서대로 나열하며, 그룹 머리글을 누르면 해당 그룹에 초점을 옮긴다. 그룹이 하나면 머리글 없이 탭만 나열한다. 행은 제목과 흐린 폴더 경로, 미리보기 탭의 기울임꼴, 저장하지 않은 변경 점을 탭과 같게 표시한다. 활성 그룹의 활성 탭은 진한 배경, 다른 그룹에 보이는 탭은 옅은 배경이다. 행을 누르면 그 그룹에서 탭을 활성화하고, 행을 끌면 탭과 같은 끌기 데이터로 다른 그룹에 옮기거나 복사한다. 닫기(X)는 활성 탭과 마우스를 올린 행·초점 행에 보이고 hover가 없는 터치 기기에서는 항상 보이며, Delete 키로도 닫는다. 닫기는 탭 닫기와 같은 `closeTab`을 호출하므로 저장하지 않은 변경 확인과 빈 그룹 제거도 같다.

한 번 연 노트는 기울임꼴 미리보기 탭이 되며 다음 미리보기 노트로 대체된다. 두 번 클릭하거나 Ctrl/⌘ 클릭하면 탭을 고정한다. 그래프는 노트 경로와 구분하는 예약 식별자 `@graph`를 가진 고정 편집기 탭이며 활성 탭의 URL은 `/graph`다. 그래프 탭도 노트 탭처럼 그룹 안에서 순서를 바꾸거나 다른 그룹으로 드래그하고 분할·닫기·다시 열기를 실행한다. 탭 메뉴에서 고정·닫기·다른 탭 닫기·옆에 열기를 실행하며 가운데 마우스 버튼으로도 닫는다. 닫은 탭은 최대 20개까지 다시 연다. 활성 노트 탭은 정식 노트 URL을 유지한다. 각 편집기 그룹은 자체 제목·닫기 헤더와 높이를 채우는 독립 본문을 가지며 노트의 읽기 위치를 유지한다. Alt 클릭으로 옆 그룹에 다른 노트를 열며 그룹 안의 노트 링크는 그 그룹에서만 이동한다. 활성 그룹은 포인터와 초점으로 추적하고 그룹 초점 명령은 해당 그룹의 본문으로 초점을 옮긴다. 데스크톱에서는 오른쪽·아래 분할과 탭의 가장자리 드롭으로 가로·세로 중첩 레이아웃을 만들며 그룹은 최대 6개다. 767px 이하는 그룹을 세로로 나열한다. 분할 구분자의 더블클릭은 해당 분할의 자식 그룹을 같은 비율로 복원한다. 마지막 탭을 닫으면 `/wiki?empty=1`에서 빈 상태와 색인 열기 버튼을 표시한다.

탭을 미리보기로 열지 고정으로 열지는 VS Code 기본 설정을 따른다. 탐색기·즐겨찾기·검색 결과·백링크·그래프 노드처럼 목록을 훑어보는 동작은 미리보기로 열어 그룹마다 하나뿐인 미리보기 탭을 그 자리에서 대체한다. 빠른 열기(Ctrl/⌘ P)는 고정 탭으로 연다(`workbench.editor.enablePreviewFromQuickOpen: false`). 노트 본문·편집기·도니 답변의 링크를 따라가도 고정 탭으로 연다. 이것은 코드 이동을 고정으로 여는 `workbench.editor.enablePreviewFromCodeNavigation: false`에 해당한다. 같은 노트 안의 소제목 링크는 탭을 고정하지 않는다. 이전에는 이 두 경로도 미리보기 탭을 갈아끼워서 링크를 따라갈 때마다 직전 노트 탭이 사라졌다. 새 노트 만들기, 중복 후보 비교, 탭 끌기, 편집 시작도 탭을 고정한다. 탐색기의 Ctrl/⌘ 클릭은 VS Code에서는 다중 선택이지만 이 앱에는 다중 선택이 없으므로 고정 탭으로 여는 동작을 유지한다.

그룹을 지정하지 않고 노트를 열면 항상 활성 그룹에 연다(`workbench.editor.revealIfOpen: false`). 이전에는 그 노트가 다른 그룹의 활성 탭이면 그 그룹으로 초점만 옮겨서, 같은 노트를 현재 그룹에 나란히 열 수 없었다. 브라우저 뒤로·앞으로 이동만 아래 주소창 규칙에 따라 이미 보여 주는 그룹을 활성화한다.

주소창은 활성 그룹의 활성 탭을 따른다. 다른 그룹을 누르거나 초점을 옮기면 `router.replace`로 그 노트 URL(`?ref=` 포함)로 바꾸고 새 이력 항목은 만들지 않는다. 노트를 여는 동작은 `router.push`다. 뒤로·앞으로 이동한 경로를 이미 다른 그룹이 보여 주고 있으면 그 그룹을 활성화하고, 아니면 활성 그룹 안에서 미리보기 탭 규칙으로 연다. 같은 노트를 여러 그룹에 열면 처음 연 그룹의 리더만 편집 상태와 저장 확인을 소유하고 나머지는 `다른 그룹에서 편집 중 · 읽기 전용`으로 표시한다.

탭은 끌어서 같은 탭 줄 안의 순서를 바꾸거나 다른 그룹의 탭 줄·본문으로 옮긴다. 놓을 때 Ctrl/⌘ 또는 Alt를 누르고 있으면 원래 탭을 남기는 복사가 된다. 본문 위에서는 포인터 위치에 따라 가운데(그 그룹에 열기)와 상하좌우 가장자리(그 방향에 새 그룹으로 분할) 영역을 반투명 사각형과 `여기에 열기`·`오른쪽으로 분할` 같은 라벨로 미리 보여 준다. 미리보기 사각형과 영역 판정은 본문만이 아니라 탭 줄을 포함한 그룹 전체를 기준으로 한다. 본문만 덮으면 새 그룹이 기존 창 안에 끼워지는 것처럼 보였기 때문이다. 그룹의 하나뿐인 탭을 자기 그룹 가장자리에 놓는 분할, 6개 그룹 상한에서의 분할, 767px 이하 화면의 가장자리 분할은 제공하지 않는다. 상한에서 분할을 요청하면 대상 그룹에 열고 알림으로 이유를 알린다. 옮긴 탭은 고정되고, 탭을 모두 옮긴 그룹은 닫힌다. 탐색기·즐겨찾기·최근 노트·검색 결과·백링크 목록·그래프 노트 목록의 노트는 조회자도 끌어서 원하는 그룹의 탭 줄·본문·분할 위치에 열 수 있다. 탐색기 폴더로 끌어 놓는 이동은 편집자 이상이 탐색기 행을 끌 때만 적용하며 접힌 폴더 위에 약 0.6초 머무르면 폴더를 펼친다. 끌기 데이터 형식은 `web/components/workspace/dnd.ts`의 노트 경로(`application/x-llmwiki-note`)와 탭(`application/x-llmwiki-tab`) 두 가지다.

저장하지 않은 초안이 있는 탭을 다른 그룹으로 옮기거나 분할 구조가 바뀌어 리더가 다시 마운트되어도 기준 버전·초안·라이브 또는 원문 표시를 메모리에서 유지한다. 경로별 저장 세션은 진행 중 요청과 후속 자동 저장도 이어받아 같은 노트에 저장 요청이 겹치지 않는다. 초안은 브라우저 저장소에 쓰지 않는다. 의도적인 탭 닫기·노트 교체는 정상 상태에서는 즉시 저장을 시작하고 이동하며 충돌·오류 상태에서는 저장하지 않은 변경을 잃는지 확인한다.

움직임은 `web/app/motion.css`의 공통 토큰(120·180·240ms, ease-out 계열)만 사용한다. 탭 열기·닫기·순서 변경은 남은 탭이 미끄러지는 FLIP 애니메이션, 끌기 중에는 삽입 위치 표시줄과 원본 탭 흐림, 새 그룹은 분할 방향에서 미끄러져 들어오고 그룹 추가·제거·비율 복원 때 이웃 그룹의 크기가 부드럽게 바뀐다. 사용자가 구분자를 끄는 동안에는 크기 전환을 끈다. 기본 사이드바·도니 패널의 버튼 접기, 활동 표시줄 선택 표시, 탐색기 폴더 펼치기, 알림 등장·퇴장, 팔레트·모바일 서랍, 드롭다운도 같은 토큰으로 움직인다. 운영체제의 동작 줄이기(`prefers-reduced-motion: reduce`)를 켜면 모든 전환과 애니메이션을 즉시 끝낸다.

셸 상태는 계정별 `llmwiki.shell.v2.<userId>`에 `selected`, `collapsed`, `width`, `chatCollapsed`, `chatWidth`를 저장한다. v2가 없으면 v1을 읽되 유효한 패널과 크기만 복원하고 크기는 허용 범위로 제한한다. 제거된 chat/admin 선택은 탐색기로 대체하며 잘못된 JSON은 기본값을 쓴다. 해당 계정의 복원이 완료된 키에만 저장해 계정 전환 중 다른 상태를 덮어쓰지 않는다.

편집기 상태는 계정별 `llmwiki.workspace.v2.<userId>`에 그룹별 열린 탭·활성 경로, 가로·세로 분할 트리와 비율, 활성 그룹, 닫은 탭·최근 노트·즐겨찾기·읽은 제목을 저장한다. v2가 없으면 v1의 기본 탭·옆 노트와 `splitRatio`를 그룹과 분할 트리로 이관한다. 그래프 탭도 그룹·분할과 함께 복원하지만 최근 노트·즐겨찾기·노트 제목 목록에는 넣지 않는다. 탐색기 필터·폴더 확장과 접은 뷰 목록(`closedViews`: `editors`·`favorites`·`tree`)도 계정별 `llmwiki.explorer.v1.<userId>`에 보관하며 `closedViews`가 없는 이전 값은 모든 뷰를 펼친 상태로 읽는다. 이 상태는 다른 기기와 동기화하지 않으며 저장소를 사용할 수 없어도 현재 세션 탐색은 동작한다. 모바일·데스크톱 전환에서는 그룹을 유지하고 데스크톱 분할 트리와 사이드바 너비·접힘을 복원한다.

하단에는 활성 노트 경로, 읽은 스냅샷의 짧은 `updatedSha`, 본문 단어·줄 수, 보기·편집·원문 표시와 저장 중·저장됨·충돌·저장 오류, 편집 커서 줄·열, 테마와 실시간 연결 상태를 표시한다. 그래프가 활성 탭이면 그래프 이름만 표시하고 노트 스냅샷·본문 통계·편집 및 저장 상태는 표시하지 않는다. 테마와 실시간 연결 상태는 그대로 유지한다. 연결 표시는 공통 `useLiveConnection` 훅을 사용하며 셸에서 별도 SSE 연결을 열지 않는다.

### 노트 작성과 파일 작업

`/api/me`의 편집자·관리자에게만 편집과 파일 변경 작업을 표시한다. 현재 노트를 소유한 그룹은 CodeMirror 6 라이브 미리보기 편집기를 기본으로 사용하며 본문은 항상 편집할 수 있다. Markdown 원문이 유일한 진실 원천이고 decoration과 widget은 표시만 바꾸며 원문을 다시 쓰지 않는다. 더보기 메뉴·명령 팔레트·Ctrl/⌘ E는 같은 편집기를 원문 표시로 전환하며 monospace·줄 번호·frontmatter를 보여 준다. 조회자, 다른 그룹이 소유한 노트, `?ref=` 과거 버전은 기존 Markdown 읽기 렌더러와 속성·DOM 목차를 유지한다. 라이브 편집의 속성은 frontmatter 위젯 안에 표시하며 목차는 편집기가 수집한 제목을 사용한다. 표시 규칙과 위젯 구조는 [라이브 미리보기](live-preview.md)에 기록한다.

변경한 탭은 자동으로 고정되고 탭과 하단 상태에 수정 표시를 남긴다. 마지막 입력 2초 뒤 자동 저장하고 연속 입력 중에도 최대 20초마다 저장을 시작한다. 각 저장은 git 커밋이므로 입력마다 커밋하지 않도록 지연과 최대 대기를 함께 둔다. 기본 커밋 메시지는 `docs(wiki): update <제목>`이다. Ctrl/⌘ S와 모두 저장은 대기를 취소하고 즉시 저장한다. 저장·이미지 업로드 중에도 편집은 계속되며 저장 응답은 기준 스냅샷만 갱신하고 그사이 입력한 초안은 유지한다. 남은 변경은 후속 자동 저장으로 처리한다. 별도 변경 버리기 명령과 Escape 초기화는 없다.

저장·원문 표시 전역 명령은 활성 그룹의 활성 경로와 `exactPath=true`로 대상을 정한다. 같은 경로를 여러 그룹에 열면 상태를 소유한 Reader만 처리한다. 저장 단축키는 셸이 처리하므로 편집기 밖에 초점이 있어도 활성 노트를 즉시 저장한다. 모두 저장은 모든 그룹에서 소유한 변경 경로를 중복 제거해 저장한다. 새 노트 명령은 exactPath를 넣지 않아 활성 노트의 부모 폴더를 제안하며 새 노트·이름 변경·삭제는 탐색기 리스너가 한 번만 처리한다.

저장은 `PUT /api/notes`에 `path`, `content`, 마지막 저장 스냅샷의 `baseSha`, `message`를 보낸다. 노트 저장과 이미지 업로드는 같은 경로별 직렬 큐를 사용해 기준 SHA 갱신이 겹치지 않는다. `main.updated`와 조회 갱신에서 외부 변경을 발견하면 깨끗한 초안은 최신 스냅샷을 받아 선택·스크롤을 보존하는 최소 diff로 적용하고, 수정 중인 초안은 유지한 채 즉시 저장을 시도한다. `409 stale_note`는 자동 저장을 멈추고 기준 버전과 내 변경, 기준 버전과 최신 저장소 내용을 공통 DiffView로 비교한다. 최신 버전 불러오기, 내 내용 복사, 명시적인 확인 후 최신 SHA 위에 내 내용으로 덮어쓰기를 제공한다. 다른 저장 실패도 자동 저장을 멈추고 다시 시도로 재개한다. 충돌 창을 닫거나 계속 입력해도 자동 저장은 재개하지 않는다.

저장되지 않은 변경이 있는 상태에서 탭 닫기·다른 노트 이동·뒤로 가기를 실행하면 정상 상태에서는 즉시 저장을 시작하고 이동을 허용하며 요청은 리더가 사라진 뒤에도 완료된다. 충돌·오류 상태에서는 저장하지 않은 변경을 잃는지 확인한다. 페이지 종료는 변경 또는 진행 중 쓰기가 있으면 브라우저 경고를 요청하며 종료 뒤 요청 완료를 보장하지 않는다. 줄별 작성자는 변경을 먼저 저장한 뒤 연다.

탐색기의 도구 모음과 파일·폴더 메뉴에서 새 노트를 만들며 경로와 제목·태그를 입력한다. 새 노트에는 `title`, `tags`, `updated` frontmatter를 넣는다. 폴더는 가상 위치로 먼저 선택하며 첫 노트를 저장해야 저장소에 남는다. 파일 메뉴는 오른쪽 클릭, Menu 키·Shift F10, 모바일의 더보기 버튼으로 연다. F2는 파일명을 인라인으로 바꾸며 이동은 폴더 선택기나 폴더로 끌어 놓기로 실행한다. 이름과 경로를 바꾸면 탭·URL·최근 노트·즐겨찾기를 함께 바꾸지만 본문에 작성한 위키 링크는 자동 수정하지 않는다. 삭제 확인에는 `/api/links`에서 읽은 역링크 수를 표시한다. 경로·위키 링크 복사와 해당 파일의 이력 열기도 제공한다.

이름 변경·이동·삭제는 영향받는 노트의 진행 중 자동 저장과 이미지 업로드를 기다리고 남은 변경을 저장한 뒤 기준 SHA를 읽는다. 저장 충돌·오류가 남으면 파일 작업을 멈춘다. 이름을 바꾸면 메모리의 저장 세션과 임시 초안도 새 경로로 옮기며 삭제하면 해당 상태를 제거한다.

이동 대상이 이미 있으면 별도로 교체를 확인한다. 현재 서버 접점은 원자적인 덮어쓰기 이동을 제공하지 않으므로 기존 대상 삭제와 원본 이동을 두 커밋으로 실행한다. 두 번째 단계가 실패해도 원본은 남으며 최신 SHA로 다시 시도한다. 삭제한 대상은 변경 이력에서 복원한다.

편집기에 PNG·JPEG·GIF·WebP 이미지를 붙이거나 끌어 놓으면 chat 목적 업로드를 만든 뒤 `assets/<날짜>/<이름>`에 저장하고 노트 기준 상대 이미지 링크를 넣는다. 이미지 저장은 노트 저장과 별도 커밋이므로 초안을 버려도 이미지 자산은 남는다. `GET /api/notes/raw?path=&ref=`는 assets 아래의 실제 이미지 바이트를 지정한 커밋에서 읽고 실제 형식의 Content-Type과 `nosniff`를 반환한다. 인증과 폴더 읽기 권한을 적용하며 경로 탈출·심볼릭 링크·HTML·SVG·지원하지 않는 형식은 거절한다. 렌더러는 노트 기준 상대 assets 경로와 과거 버전의 ref를 이 접점에 전달한다.

`/wiki/<경로>?ref=<SHA>`는 작성자·날짜·짧은 SHA와 읽기 전용 배너를 표시한다. 현재 버전 열기와 `/history/compare?base=<ref>&head=main&path=<경로>` 비교를 제공한다. 편집자 이상은 현재 버전과 복원 내용을 먼저 비교하고 확인한 뒤 현재 `baseSha`로 저장하며 `revert(wiki): restore <경로> to <짧은 SHA>` 커밋을 남긴다. 줄별 이력 토글은 공통 BlameView를 표시한다. 노트 전체의 `이 노트에 대해 묻기`와 선택한 본문의 `도니에게 묻기`는 경로·스냅샷·선택문을 새 도니 대화의 고정 문맥으로 넘긴다. 명령 팔레트에서도 새 노트, 원문 편집 전환, 즉시 저장, 이름 바꾸기, 삭제, Blame 토글, 도니에게 묻기를 실행한다.

### 검색과 지식 탐색

`/search`와 사이드바 검색 패널에서 검색어는 입력 중 임시값으로 두며 Enter 또는 전체 화면의 검색 버튼을 눌렀을 때 제목 제안과 전체 검색을 실행한다. 검색어의 시작이나 공백 뒤에서 `#`를 입력하면 커서 위치에 관계없이 태그 추천을 열고, ↑·↓로 추천을 선택한 뒤 Enter·Tab 또는 마우스로 태그 필터를 추가하면 해당 `#` 토큰을 검색어에서 제거한다. Escape는 추천만 닫고 입력한 텍스트를 유지하며, 한글 IME 조합 중에는 태그 추천을 처리하지 않고 `compositionend` 이후에 처리한다. 추천이 비어 있을 때 Enter는 일반 검색을 실행한다. 작성자 조건은 Enter 또는 입력란을 벗어날 때 커밋한다. 사용자가 요청한 명시적 검색 방식으로 입력할 때마다 발생하던 반복 요청과 브라우저 이력 항목 누적을 막는다. 폴더·태그·날짜 선택과 칩 제거·필터 초기화는 선택 즉시 적용한다. URL에는 `q`, `folder`, `tags`, `from`, `to`, `author`를 유지하며 브라우저 이력은 검색어 또는 필터 조건이 커밋되어 달라졌을 때만 추가한다. 뒤로·앞으로 이동하면 입력과 결과 조건을 복원한다. 한글 IME 조합 중에는 검색을 제출하거나 결과를 열지 않으며, 새 검색을 불러오는 동안에도 이전 결과를 흐리게 유지하고 조회 중임을 표시한다. 적용 중인 필터는 필터 영역을 접어도 검색 입력 아래에 항상 보이며, 태그마다 별도 칩을 표시하고 각 칩의 제거 버튼과 `모두 지우기`로 해제한다. 필터 버튼의 숫자는 선택한 태그 각각을 포함한 활성 칩 수다. 선택하지 않은 인기 태그는 노트 수 내림차순으로 검색 입력 아래의 빠른 선택 줄에 표시하며, 전체 검색에서는 최대 10개, 좁은 사이드바에서는 최대 5개를 제공한다. 폴더는 노트 트리에서 선택하고 태그는 색인의 노트 수와 함께 토글 칩으로 여러 개를 선택한다. 태그 선택기는 선택한 태그, 노트 수 내림차순, 한글 이름순으로 정렬하고 처음에는 최대 30개를 표시하며 `모두 보기`와 `접기`로 나머지를 펼치거나 접는다. 태그 이름 검색은 NFKC 정규화, 소문자 변환, 앞뒤 공백과 선행 `#` 제거, 내부 공백의 `-` 변환을 적용하며 일치하는 태그는 개수 제한 없이 표시한다. 태그 이름 입력란에서 Enter를 누르면 일치하는 미선택 태그 중 첫 태그를 선택하고 입력을 비우며 전체 검색을 제출하지 않는다. 색인에 없는 선택 태그도 `미색인`으로 표시해 해제할 수 있다. 선택한 태그는 모두 포함해야 하며 작성자 조건은 마지막 수정 커밋의 이름·이메일을 찾는다. 수정일은 날짜 입력으로 선택하며 URL의 ISO datetime 값은 칩과 검색 조건에 보존한다. 종료에 날짜만 넣으면 UTC 기준 그날 전체를 포함한다. 비어 있지 않은 검색어와 당시 필터는 사용자별 localStorage의 `llmwiki.search.recent.v1.<userId>`에 최근 검색으로 저장한다. 최근 검색은 검색어와 필터가 같은 항목을 중복 제거해 최신순으로 최대 8개까지 보관하며, 다시 실행하거나 개별 삭제하고 전체 목록을 지울 수 있다. 저장소 읽기·쓰기가 실패해도 현재 검색은 동작한다.

검색어의 태그 자동완성은 이미 선택한 태그를 제외하고 이름에 입력한 문자열이 포함된 태그를 최대 8개 표시한다. 접두어 일치, 노트 수 내림차순, 한글 이름순으로 정렬하며 `#`만 입력하면 인기 태그를 표시한다. 커서를 태그 토큰 중간으로 옮겨 선택해도 토큰 전체를 제거하고 커서를 남은 검색어 사이에 유지한다. 추천이 비어 있으면 `일치하는 태그가 없습니다`를 표시하며 입력란을 벗어나면 추천을 닫는다.

결과에는 제목·경로 breadcrumb·소제목·태그·마지막 수정 시각을 표시한다. 결과의 태그 배지는 노트를 여는 링크 밖의 토글 버튼이며, 누르면 노트를 열지 않고 해당 태그 필터를 추가하거나 해제한다. 서버의 UTF-16 highlight 범위를 본문 조각의 `<mark>`로 렌더링하고 결과를 열면 `/wiki/<path>#<anchor>`에서 해당 소제목으로 이동한다. ↑·↓로 제목 제안과 결과를 선택하고 Enter로 연다. Ctrl/⌘ Enter 또는 나란히 열기로 결과를 분할에 열며 검색 화면에서 실행하면 최근 기본 노트로 돌아간다. 다음 결과는 `nextCursor`로 스크롤할 때 자동 조회하며 직접 더 불러오기와 자동 조회 끄기도 제공한다. 커서는 5분 뒤 만료할 수 있으므로 오류 상태에서 처음부터 검색하거나 해당 페이지를 재시도한다.

의미 검색을 사용할 수 없을 때는 중립적인 `키워드` 라벨을 표시한다. API 키 없음·임베딩 서비스 실패·벡터 모델/차원 불일치·실제 색인 지연처럼 검색이 저하된 구체적인 원인이 있을 때만 경고한다. 의미 검색이 준비되면 `의미 + 키워드` 라벨을 표시한다. 검색 결과는 `index.updated`에서 다시 읽으며 공용 실시간 스트림만 사용한다.

백링크 패널은 현재 노트의 역링크·나가는 링크·미해결 링크와 의미상 유사를 구분한다. 의미상 유사는 명시적인 링크의 목록이 아니며 임베딩이 준비되지 않았을 때 빈 결과일 수 있다. 편집자 이상은 미해결 링크에서 대상 경로가 채워진 새 노트 대화상자를 열고 조회자는 대상 노트의 빈 상태를 연다. 그래프 탭이 활성화되면 노트를 먼저 열도록 안내한다. `main.updated`와 `index.updated`에서 링크·유사 노트·태그·그래프·중복 후보를 다시 읽는다.

백링크 패널도 탐색기와 같은 접이식 뷰(`web/components/workspace/view-pane.tsx`의 `ViewHeader`)로 역링크·나가는 링크·미해결 링크·의미상 유사를 나눈다. 머리글 오른쪽에 개수를 표시하고 각 뷰의 목록은 `min(14rem, 30vh)` 높이 안에서 따로 스크롤한다. 이전에는 네 목록이 한 스크롤 영역에 이어지고 빈 목록마다 `0`과 빈 상태 안내를 띄워서, 한 노트에 링크가 몇 개뿐이어도 패널이 길어지고 실제 항목을 찾기 어려웠다. 그래서 항목이 없는 뷰는 숨기고, 의미상 유사는 불러오는 중이거나 오류가 났을 때도 뷰를 보여 준다. 네 뷰가 모두 비면 임베딩 미준비 가능성을 함께 알리는 빈 상태 하나만 표시한다. 접힘 상태는 패널이 마운트된 동안만 유지하며 브라우저 저장소에는 쓰지 않는다.

태그 패널과 `/tags`는 이름 필터와 태그별 노트 수를 제공하며 `/tags/[tag]`에서 해당 노트를 읽거나 분할에 연다. 노트 속성의 태그 배지도 이 경로로 연결한다. 태그 경로는 한 번만 디코딩하여 한글과 리터럴 `%` 이름을 보존한다.

`/graph`는 노트 옆에 고정되는 그래프 편집기 탭을 열며 다른 노트 탭처럼 분할·이동한다. 클라이언트 전용 force graph는 편집기 그룹의 가용 너비와 높이를 채우고 읽기 권한이 있는 전체 노트를 고립 노트까지 항상 표시한다. 중심 노트·연결 깊이·지역 그래프는 사용하지 않으며 URL 질의로 범위를 바꾸지 않는다. 캔버스 위의 조밀한 도구 모음은 제목·경로 검색, Enter로 첫 결과에 초점 이동, 새로고침, 전체 맞춤과 노트·링크 수를 제공한다. 전체 맞춤은 도구 모음과 범례에 노트가 가리지 않도록 72px 여백을 둔다. hover는 제목·경로를 표시하고 해당 노트와 이웃·연결선을 강조하며 나머지를 흐리게 한다. 각 그룹에서 활성화된 노트는 고리로 표시하되 자동으로 화면 중심을 옮기지 않는다. 노트를 누르면 그래프가 속한 그룹에 열고 Ctrl/⌘/Alt 클릭은 옆 그룹에 연다. 최상위 폴더 색상 범례는 폴더 강조를 토글하며 노트 크기는 연결 수, 화살표는 링크 방향을 나타낸다. 폴더 색은 정렬한 폴더 순서대로 다섯 개의 의미 색 토큰을 순환 배정한다. 이전의 이름 해시 배정은 폴더가 두세 개뿐인 저장소에서도 같은 색이 겹쳤기 때문이다. 접을 수 있는 키보드 노트 목록은 검색 결과·연결 수·초점 버튼·열기 링크를 제공하며 행을 작업 공간으로 끌어 놓을 수 있다. 강조·검색 결과·활성 노트의 제목은 항상 표시하고 다른 제목은 노트 수에 따른 확대 배율에서만 표시한다. CSS 의미 토큰으로 밝은·어두운 테마를 반영하고 확대·맞춤 애니메이션은 동작 줄이기 설정을 따른다. 반발력과 약한 가로·세로 중심 힘으로 고립 노트가 멀어지는 것을 줄이며 배치 계산은 최대 150 tick 또는 6초 뒤 멈춘다.

`/search/duplicates`는 중복 후보의 정확한 내용 일치·의미 유사 이유와 점수, 양쪽의 일치 구절과 소제목 링크를 표시한다. 비교는 왼쪽 노트를 고정 기본 탭, 오른쪽 노트를 분할로 열며 자동 병합·삭제하지 않는다. 점수는 확정 판정이 아니며 의미 기반 후보는 준비된 임베딩만 사용한다. 검색 헤더와 명령 팔레트의 그래프 열기는 현재 편집기 그룹에 고정 그래프 탭을 열며 태그 보기·백링크 패널·중복 후보도 제공한다.

### 단축키와 테마

`web/components/workspace/keybindings.ts`가 실행·도움말·팔레트 힌트의 단일 레지스트리다. Mac에서는 ⌘/⌥/⇧, 다른 플랫폼에서는 Ctrl/Alt/Shift로 표시한다.

| 단축키 | 동작 |
| --- | --- |
| Ctrl/⌘ S | 활성 그룹 노트의 자동 저장 대기를 취소하고 즉시 저장한다. |
| Ctrl/⌘ Alt S | 모든 그룹의 변경된 노트를 즉시 저장하며 동일 경로는 중복 제외한다. |

| Alt N | 새 노트를 만든다. |
| Alt W | 활성 그룹의 활성 탭을 닫는다. 그룹의 마지막 탭이면 그룹도 닫는다. |
| Alt ← / → | 활성 그룹의 이전/다음 탭을 선택한다. |
| Alt 1–9 | 활성 그룹의 탭을 번호로 선택한다. |
| Alt Shift T | 닫은 탭을 다시 연다. |
| Ctrl/⌘ B | 기본 사이드바를 접거나 펼친다. |
| Ctrl/⌘ Alt B | 도니 패널을 접거나 펼친다. |
| Ctrl/⌘ Alt I | 도니를 열고 초점을 옮긴다. |
| Ctrl/⌘ Shift O | 새 도니 대화를 연다. |
| Ctrl/⌘ Shift E / F / H | 탐색기/검색/이력 패널에 초점을 옮긴다. |
| Ctrl/⌘ , | 설정을 연다. |
| Ctrl/⌘ \\ | 활성 탭을 오른쪽 새 그룹으로 분할한다. |

빠른 열기는 경로 퍼지 검색과 서버 제목 제안을 제공하고 `#`는 소제목, `>`는 명령을 찾는다. 팔레트 안에서는 ↑·↓로 항목을 선택하고 Enter로 실행하며 Escape로 닫는다. 명령 팔레트는 노트·패널·분할·탭·이력·즐겨찾기·테마와 [운영 명령](operations.md#웹-운영-화면과-지금-실행)을 제공한다. 모달은 초점을 가두고 닫을 때 원래 요소로 복원한다.

브라우저 예약 키는 웹에서 안정적으로 가로챌 수 없다. 예를 들어 Chrome의 닫은 브라우저 탭 복원 키였던 Ctrl/⌘+Shift+T 대신 노트 탭 복원은 Alt Shift T를 사용한다. IME 조합과 keyCode 229는 무시하고 Alt 노트·탭 단축키와 `?`는 입력 영역에서 실행하지 않는다.

`next-themes`가 시스템·밝게·어둡게를 제공하며 `llmwiki.theme`에 선호를 저장한다. 헤더 메뉴와 `/settings?tab=appearance`는 세 값을 직접 선택하고 상태 표시줄은 시스템→밝게→어둡게→시스템으로 순환한다. 초기 HTML 스크립트가 수화 전에 클래스를 적용해 잘못된 테마가 먼저 번쩍이지 않게 한다. 렌더러·편집기·그래프의 테마 갱신과 지연 로딩은 [읽기 성능](performance.md#프런트엔드-읽기-비용)을 따른다.

### 노트 렌더링과 링크

GFM 표·목록과 함께 `rehype-highlight` 코드 강조와 복사 버튼, `remark-math`·`rehype-katex` 수식, Mermaid fenced block을 표시한다. Mermaid는 strict 보안 모드를 사용하며 파싱 실패 시 오류와 원문을 표시한다. 원시 HTML은 실행하거나 렌더링하지 않는다. 공유 Markdown의 메모이제이션·Mermaid 지연 로딩은 [읽기 성능](performance.md#프런트엔드-읽기-비용)에 기록한다.

`> [!note] 제목` 같은 Obsidian callout을 표시하며 종류 뒤의 `-`는 처음 접힘, `+`는 처음 펼침인 접이식 callout을 만든다. 읽기 렌더러는 제목에 `rehype-slug` ID와 앵커 링크를 붙이고 실제 DOM 제목과 IntersectionObserver·스크롤 위치로 목차와 활성 제목을 추적한다. 편집기의 목차와 fragment 이동은 Markdown 제목의 같은 slug를 사용하며 편집기 핸들로 이동한다. 두 경우 모두 해당 그룹의 바깥 읽기·편집 영역이 스크롤을 소유한다.

frontmatter 속성 패널은 제목·날짜·중요도 같은 알려진 필드와 문자열·숫자·불리언 같은 스칼라 필드를 안전하게 표시하며 임의 객체를 HTML로 해석하지 않는다. 태그 배지는 `/tags/<tag>`로 연결한다.

`[[폴더/노트#제목|별칭]]`과 상대 `.md` 링크는 경로·별칭·fragment를 유지하며 앱 안에서 연다. 공백을 포함한 제목 fragment는 렌더링 제목과 같은 slug로 바꾼다. 코드 안의 위키 링크 문자열은 변환하지 않는다. 해결된 링크는 hover 또는 키보드 초점에서 기존 노트 내용 API를 사용한 제목·본문 미리보기를 제공하며 조회 캐시를 공유한다. 없는 링크와 같은 이름의 후보가 여러 개인 링크는 서로 다른 표시로 남겨 임의 노트로 이동시키지 않는다. 이름 해석은 기존 `{path}` 응답과 `{path,candidates}` 응답을 모두 읽는다.

### REST API와 저장 규칙

웹 API는 `/api` 아래에 있으며 웹은 세션으로 인증한다. 같은 API는 `SessionGuard`를 통해 REST Bearer 토큰도 받으며 읽기·쓰기 scope와 만료·회수 정책은 [인증과 권한](auth.md)을 따른다. `viewer`도 위키·검색·이력·질의응답을 이용할 수 있고, `/api/admin`은 `admin`만 이용할 수 있다. 오류는 HTTP 상태와 함께 `{error:{code,message}}` 형태로 반환한다. 마지막 관리자를 삭제하거나 다른 역할로 내리려 하면 `409`와 `last_admin` 코드를 반환한다.

`src/api/api.module.ts`는 현재 사용자·노트·검색·이력·쓰기 작업·대화·관리 API뿐 아니라 업로드·생성 작업·대화 모델·링크·그래프·태그 컨트롤러도 등록한다. 각 컨트롤러는 `SessionGuard`로 웹 세션 또는 REST Bearer 토큰을 검사하며 역할 제한이 필요한 접점에는 `RolesGuard`와 `@Roles`를 적용한다. 입력은 `api.dto.ts`의 Zod 스키마와 공용 `ZodValidationPipe`로 검증하고 오류 응답은 전역 HTTP 예외 필터가 만든다. `NotesService`는 노트 읽기와 이름 해석을, `HistoryService`는 git 이력과 쓰기 작업 연결·요청자 표시를 담당한다.

| 접점 | 용도 |
| --- | --- |
| `GET /me` | 현재 사용자를 반환한다. |
| `GET /notes/tree`, `/notes/content?path=`, `/notes/resolve?name=` | main의 마크다운 목록, 원문·frontmatter·본문·`updatedSha`, 위키 링크의 노트 경로를 반환한다. |
| `GET /search?q=&folder=&tags=&from=&to=&author=&cursor=&limit=` | 검색 모드·축소 원인·소제목 anchor·highlight와 다음 커서를 반환한다. |

| `GET /links?path=`, `/graph`, `/tags`, `/tags/notes?tag=` | 노트 연결·태그와 태그별 노트를 반환한다. graph는 매개변수 없이 항상 읽을 수 있는 모든 노트의 전체 그래프를 반환한다. |

| `POST /conversations/:id/messages/:mid/proposal` | 답변에서 새 노트나 수정 초안을 만들며 저장하지 않는다. |
| `/admin/users`, `/admin/settings` | 사용자와 역할, 허용 목록 사용 여부와 허용 도메인 설정을 관리한다. |

표의 경로 앞에는 `/api`를 붙인다. 노트 내용은 지정한 `ref` 또는 생략 시 main HEAD를 커밋 SHA로 고정한 뒤 같은 커밋에서 읽으므로 `updatedSha`는 본문과 일치하는 저장소 스냅샷이다. `path`는 저장소 상대 `.md` 경로이며 절대 경로·상위 경로·git 메타데이터 경로는 거절한다. 위키 링크 이름 해석은 폴더 경로를 받을 수 있고 `#fragment`를 제외한다. 응답은 `{path,candidates}`이며 같은 basename 후보가 여러 개이면 `path:null`과 후보 목록을 반환하여 사용자가 선택한다. 후보가 없으면 `404`다.

목록의 `limit`은 기본 50, 최대 100이다. 변경 이력의 `before`는 마지막 커밋 SHA이며 해당 커밋보다 오래된 결과를 요청한다. 쓰기 작업의 `before`는 마지막 작업의 ID다. 커밋과 쓰기 작업은 작업의 `commits` 배열 또는 `mergeSha`로 연결한다. 요청자가 삭제되어도 쓰기 작업 이력은 남으며 요청자 표시는 이메일 대신 `deleted user`, 이름 대신 `null`을 반환한다.

대화는 `conversations`, 메시지는 `messages`, 구성원은 `conversation_members`, 생성 작업은 `generations`, 순서가 있는 SSE 프레임은 `generation_frames`에 저장한다. 대화 목록은 최근 활동 순서이며 `q`는 제목과 메시지의 부분 문자열을 검색해 최대 240자 `snippet`을 추가한다. 메시지는 삽입 순서다. 구성원이 아닌 사용자의 요청은 관리자도 `404`, 대화 조회자의 변경 요청은 `403`이다. 소유자만 대화 삭제와 구성원 변경을 수행하며 자기 소유권을 제거할 수 없다. 구성원 편집자는 제목·메시지를 변경한다. 전역 `viewer`도 자신이 만든 대화의 소유자로 질문할 수 있다.

대화·메시지·생성·업로드 식별자는 응답과 SSE·실시간 이벤트에서 22자리 base62로 반환한다. 경로와 첨부 입력은 기존 UUID도 허용하므로 이전 `/chat/<uuid>` 북마크와 저장된 마지막 스레드를 계속 열 수 있다. DB의 ID 열과 메시지 첨부 배열은 base64url로 저장하지만 SSE 프레임의 JSON은 전송한 base62 값을 그대로 보존한다. `clientId`는 클라이언트가 정하는 불투명 문자열이므로 변환하지 않으며 사용자 ID와 SSE 순번은 정수다. 인코딩과 입력 허용 범위는 [식별자](identifiers.md)를 따른다.

제목 없이 만든 대화는 첫 질문의 공백을 정리하고 Unicode 문자 80개까지 잘라 제목을 정한다. 명시적 제목은 200자, 질문은 100,000자이며 빈 질문은 거절한다. `PATCH /conversations/:id` 입력은 `{title}`이다. `GET /conversations/:id`는 `{conversation,messages}`이며 메시지는 `{id,role,content,citations,attachments,context,status,usage,model,effort,generationId,createdAt}`이다. `generationId`는 assistant 메시지에 연결된 생성 ID이며 연결이 없으면 `null`이다. 이를 사용하면 다른 기기나 새로 연 화면에서도 실행 중 생성에 연결할 수 있다. `status`는 `completed|running|failed|cancelled|interrupted`, `usage`는 `{inputTokens,outputTokens,reasoningTokens}|null`, `context`는 `{notePath,ref?,selection?}|null`이다. `citations`는 `{path,heading?,anchor?,excerpt?,sha?}` 객체 배열이다.

`POST /conversations/:id/messages` 입력은 `{content,attachments?:string[],context?:{notePath,ref?,selection?},clientId?,model?,effort?}`이다. 첨부는 최대 10개이며 업로드 소유자만 새 질문에 첨부한다. 이전 구성원이 제출한 첨부는 권한을 검사한 대화 기록을 통해 서버에서 다시 읽는다. `model`은 `LLM_MODELS`의 선택 가능 모델명 목록에 있어야 한다. 목록은 쉼표로 나누고 각 항목 앞뒤 공백을 제거하며 빈 항목은 제외한다. 기본값은 `gpt-6-luna`이고 첫 항목을 기본 모델로 사용한다. `effort`는 `low|medium|high`이며 서버 기본 추론 강도는 `LLM_REASONING_EFFORT`(기본값 `medium`)로 설정한다. 고정 노트 문맥은 서버가 지정 ref의 정식 원문을 읽으며 selection은 신뢰하지 않는 인용문으로 다룬다.

`GET /models`는 `{models:string[],defaultModel:string,efforts:['low','medium','high'],defaultEffort:string}`을 반환한다. 서버 기본 추론 강도는 요청별 허용 목록보다 넓을 수 있으므로 기본값 선택은 `effort`를 생략한다.

SSE는 `id: <정수 seq>`, `event: <유형>`, `data: <JSON>` 뒤 빈 줄을 보낸다. 이벤트는 `generation {generationId,userMessageId}`, `status {phase}`, `tool {name,state:'start'|'end',summary,path?,jobId?}`, `citation {path,heading?,anchor?,excerpt?,sha?}`, `delta {text}`, `usage {inputTokens,outputTokens,reasoningTokens}`, `done {message}`, `error {code,message}`다. 도구 요약의 공개 범위와 `write_knowledge`의 제출문 발췌 예외는 [도니의 진행 이벤트](agent.md#모델과-호출-방식)를 따른다. `write_knowledge`의 성공한 종료 이벤트만 `jobId`를 추가하며 도구 실패에는 작업 링크를 만들지 않는다. `GET /generations/:id/events`의 `Last-Event-ID`는 해당 생성의 마지막 정수 seq이며 이후 프레임만 재생하고 실시간 프레임으로 이어진다. 완료된 생성도 재생한다.

웹의 `web/lib/chat-stream.ts`는 모든 프레임을 `{id,event,data}` 형태의 `onEvent` 콜백으로 전달한다. 연결이 끊기면 현재 연결에서 처리한 마지막 seq를 `Last-Event-ID`로 전달하며 최대 10초의 지수 백오프로 다시 연결한다. 마지막 seq는 생성 ID별 localStorage에도 저장하지만 새 화면은 저장된 본문과 cursor의 일관성을 보장할 수 없으므로 처음부터 재생해 표시 상태를 다시 구성한다. 새 질문의 최초 연결이 실패하면 같은 `clientId`로 제출을 반복해 중복 질문을 만들지 않는다. 수정·재시도·재생성은 최초 생성 ID를 받기 전까지 멱등성을 보장하지 않으므로 자동 재제출하지 않는다. 생성 ID를 받은 뒤의 재연결은 같은 생성의 이벤트만 읽는다.

HTTP 연결 종료는 생성 작업을 중지하지 않는다. 명시적 `POST /generations/:id/cancel`만 구성원 편집자나 소유자의 생성을 중지한다. 서버 재시작 시 실행 중 작업은 `interrupted`로 전환한다. 실패·취소된 답변도 부분 텍스트와 상태를 저장한다. 공급자 오류는 내부 로그에만 남기며 사용자에게 `generation_failed` 등 안전한 코드와 메시지를 전달한다. 대화에 실행 중 생성은 하나만 허용하며 중복 실행·수정·삭제는 `409 generation_active`다.

스트림 AbortSignal은 관찰만 종료하며 생성 취소를 요청하지 않는다. `cancelGeneration()`만 명시적인 중지 API를 호출한다. 생성 이후의 `error` 프레임은 콜백에 전달한 뒤 Promise를 `null`로 완료하며 `done`은 저장된 메시지로 완료한다. 생성 ID를 받기 전 오류는 콜백 이후 예외로 전달한다.

동일 대화의 동일 `clientId` 제출은 기존 생성 이벤트를 반환하며 질문을 중복 저장하지 않는다. `POST .../messages/:mid/retry`는 실패·취소·중단된 답변이나 남아 있는 사용자 질문을 재시도한다. `POST .../:mid/regenerate`는 assistant 메시지에서 이전 질문의 답변을 새로 만든다. `PATCH .../:mid` 입력은 `{content}`이며 사용자 질문만 수정한다. 이 세 경로는 같은 SSE 형식으로 응답하고 해당 질문 뒤의 턴을 삭제하며 사용자 질문을 새로 추가하지 않는다. 긴 대화는 요청자가 현재 읽을 수 있는 이력에서 오래된 턴을 요청별로 요약하고 최근 턴은 원문으로 유지한다. 요약을 저장하거나 구성원 사이에서 공유하지 않는 이유와 기준은 [도니](agent.md#엔진이-정의하는-함수-도구)에 기록한다. `010_chat.sql`의 `conversations.summary`와 `summary_through` 열은 기존 DB와 적용된 마이그레이션의 호환성을 위해 남기지만 서비스는 읽거나 쓰지 않는다. 편집·재시도·재생성도 이 열을 초기화하지 않으며 다음 답변에서 현재 남은 이력으로 요약을 다시 만든다. 아직 학습하지 않은 사용자 질문의 `learned_at`은 `NULL`이다.

수정·재생성으로 대화에서 제거한 턴의 생성 이벤트와 `clientId` 기록도 대화가 존재하는 동안 유지한다. 늦게 재전송한 이전 질문은 기존 이벤트를 재생하며 제거한 턴을 복원하지 않는다. 생성 중 요청자가 구성원에서 제거되어도 나머지 구성원에게 완성 메시지를 전달하며, 제거된 사용자의 실시간 스트림은 종료한다. 편집한 사용자 질문은 다시 미학습 상태가 되고 꿈꾸기는 수집한 질문 내용과 현재 내용이 같은 경우에만 학습 완료로 기록한다.

구성원 추가 입력은 `{email,role:'editor'|'viewer'}`이며 조회·추가는 `{members:[{userId,email,name,role}]}`를 반환한다. 삭제는 `204`다. presence 입력은 `{typing}`이며 `{expiresAt}`를 반환한다. 30초 동안 갱신하지 않은 사용자는 제거하며 `conversation.presence {conversationId,users:[{id,name,typing}]}`와 `conversation.updated {conversationId,messageId?}` 이벤트는 구성원 userIds에만 전달한다.

업로드 multipart 필드는 `file`, 선택 필드 `purpose=chat|import`이며 기본값은 `chat`이다. chat은 20 MB 이하 PNG/JPEG/WebP/GIF/PDF/UTF-8 text/Markdown이고 실제 바이트를 검사한다. import는 전역 editor 이상만 생성하며 ZIP을 추가 허용하고 100 MB 한도다. import 목적 파일은 chat 첨부로 사용할 수 없다. 응답은 `{id,userId,name,mediaType,size,createdAt,purpose}`다. 다운로드는 소유자만 가능하며 안전한 Content-Disposition과 탐지한 Content-Type을 반환한다. save 입력은 `{path,baseSha}`이고 경로는 `assets/` 아래이며 공용 NoteWriter를 통해 저장한다. 메시지에서 참조하지 않고 assets로 저장하지 않은 업로드는 `UPLOAD_RETENTION_DAYS`(기본 7일) 이후 제거한다.

임시 업로드 파일명은 응답의 base62 업로드 ID와 같다. 시작 시 기존 UUID 파일명을 같은 식별자의 base62 이름으로 옮긴 뒤 보존 기간 정리를 수행하며, 이미 옮긴 파일과 UUID가 아닌 파일명은 다시 이름을 바꾸지 않는다.

proposal 입력은 `{mode:'new'|'edit',path?}`이며 edit에는 경로가 필요하다. 완성된 assistant 답변을 기반으로 `{path,baseSha,original:string|null,proposed}` 전체 노트 초안을 반환한다. 이 호출은 커밋이나 노트 쓰기를 수행하지 않는다. 클라이언트가 diff를 확인한 뒤 별도의 노트 쓰기 접점으로 적용한다.

### 폴더별 접근 제어

`/settings?tab=acl`의 `접근 권한` 탭은 접두사별 규칙 목록, 트리 기반 폴더 선택과 정확한 파일 경로 입력, 사용자·역할·전체 주체 선택과 `none`·`read`·`write` 선택을 제공한다. 같은 주체의 규칙을 저장하면 갱신하고 삭제는 확인을 요구한다. `접근 확인`에서 사용자와 경로를 골라 실효 권한과 적용 규칙을 확인한다. 조회 실패는 빈 규칙 목록과 구분하며 다시 시도할 수 있다.

위키 목록·검색·이력·그래프·첨부 원문과 내보내기는 읽을 수 있는 경로만 반환한다. 읽지 못하는 노트를 직접 열면 없는 노트와 같은 404를 표시한다. 저장·이동·삭제·초안과 첨부 저장은 전역 역할 외에 대상 경로의 쓰기 권한도 요구한다.

공유 대화의 구성원 권한은 노트 읽기 권한을 승격하지 않는다. 각 구성원에게 읽을 수 있는 인용만 표시하고 제한된 인용·고정 문맥을 사용한 턴은 본문과 문맥도 보수적으로 가린다. 생성 이벤트와 도니의 후속 문맥에도 같은 제한을 따르며 자세한 결정과 자유 입력의 한계는 [폴더별 접근 제어](access-control.md)에 기록한다.
