# 웹 버전
웹은 지식 저장소의 위키 탐색·읽기와 근거를 제시하는 질의응답을 제공한다.

## 배경

사용자는 MCP 클라이언트 없이도 브라우저에서 지식을 읽고 바로 질문할 수 있어야 한다. 웹은 같은 지식 저장소를 사람이 직접 탐색하거나 질문으로 활용하는 접점이다.

## 내용

### 위키 탐색과 읽기

웹에서 위키를 탐색하고 노트를 읽는다. 지식 저장소의 노트와 진입점 색인 구조는 [지식 저장소](knowledge-repository.md)를 따른다. 예를 들어 사용자는 직접 관련 노트를 찾아 읽거나, 아래 질의응답을 통해 질문에 필요한 지식을 찾는다.

### 질의응답

사용자는 웹에서 지식에 대한 질문을 입력한다. Luna는 에이전트형 RAG를 사용해 답변하고 근거 노트를 인용한다. 검색과 노트 읽기를 반복하는 동작 및 메모리 파일의 문맥 주입 방식은 [RAG](rag.md)에 기록한다. 인용은 사용자가 답변의 근거 노트로 돌아가 내용을 확인할 수 있도록 하기 위한 것이다.

### 대화 기록과 학습

웹 질의응답 대화 기록은 DB에 저장한다. 대화 기록은 학습 입력으로도 사용하며, [dreaming](dreaming.md)이나 [쓰기 흐름](write-flow.md)에서 대화의 지식을 추출해 지식 저장소에 반영한다.

### 로그인과 사용자 등록

로그인과 사용자 등록 절차는 [인증과 권한](auth.md)을 따른다.

### 디자인

웹은 shadcn/ui 기반으로 깔끔하게 레이아웃을 맞춘다.

`components.json` 설정은 다음과 같다.

| 설정 | 값 |
| --- | --- |
| `style` | `base-nova` |
| `baseColor` | `neutral` |
| `cssVariables` | 사용한다. |
| `iconLibrary` | `lucide` |
| `menuColor` | `default` |
| `menuAccent` | `subtle` |

엔진 웹은 React + Vite SPA로 만든다. 이미지 빌드 때 정적 파일을 생성하고 엔진의 HTTP 서버가 그대로 서빙한다. 별도 Next.js 서버 프로세스를 띄우지 않아 [전체 구성](architecture.md)의 단일 프로세스·단일 컨테이너 요구사항에 맞추기 위한 결정이다.

## 열린 쟁점

대화 기록의 어떤 부분을 지식으로 삼을지, 언제 반영할지, 대화 공개 범위는 아직 정하지 않았다. 사용자 발화만 사용할지 Luna 답변까지 포함할지, dreaming에서 일괄 반영할지 대화 종료 시 쓰기 작업으로 반영할지, 다른 사용자의 대화 기록을 볼 수 있는지가 열린 쟁점이다.
