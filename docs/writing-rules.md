# 지식 작성 규칙

도니는 지식 저장소를 대화 기록의 덤프가 아니라 재사용할 수 있는 지식으로 유지한다.

## 배경

대화의 임시 상태를 그대로 저장하면 시간이 지난 뒤 제목·태그·속성의 의미를 이해하기 어렵고, 비슷한 노트가 흩어져 검색과 탐색도 어려워진다. 이 규칙은 저장할 내용을 먼저 판단하고 기존 지식과 연결하며, 유지할 가치가 있는 본문과 메타데이터만 남기기 위한 기준이다.

사용자가 제공한 Obsidian 규칙을 지식 저장소 작성 기준으로 옮기고, 스레드→문서 프롬프트에서는 일반적인 사실성·문체 규칙만 채택한다. 이 규칙은 지식 저장소 자체의 `AGENTS.md`에 schema로 둔다. 엔진 개발 문서의 작업 규칙과는 구분하며, 파일의 역할은 [지식 저장소](knowledge-repository.md)에 설명한다.

빈 지식 저장소의 초기 schema는 `src/knowledge/seed/AGENTS.md`에 이 문서의 규칙·예시·채택 여부를 담아 제공한다. 함께 제공하는 `MEMORY.md`는 목적만 적고, `index.md`는 실제 노트가 없는 빈 진입점 골격으로 시작하며, `raw/`, `wiki/`, `journal/`은 `.gitkeep`로 보존한다. 초기 파일에는 예시 지식이나 존재하지 않는 노트의 링크를 넣지 않는다.

## 내용

### 저장 판단과 기존 노트 활용

- 저장 전에 내용이 재사용할 규칙, 반복 가능한 패턴, 체크리스트, 색인 또는 프로젝트별 노트 중 무엇인지 판단한다.
- 새 노트를 만들기 전에 지식 저장소를 검색한다.
- 새 내용이 적합한 기존 노트에 속하면 그 노트를 확장한다.
- 독립적으로 분명한 목적이 있을 때만 새 노트를 만든다.
- 큐레이션된 탐색에서 발견되어야 하는 새 노트는 관련 색인 노트에서 연결한다.
- 오래 유지할 노트를 저장하기 전에 재사용 가능한 지식보다 현재 대화 상태를 기록하는 데 목적이 있는 제목·속성·태그를 배제한다.
- 대화를 제거했을 때 의미가 사라지는 섹션 제목은 금지한다.
- 버전, 임시 단계, 구현 세부 사항 또는 일회성 실험을 이름으로 삼는 태그는 금지한다.
- 폴더나 태그 분류를 중복하거나 읽기 진행 상태 또는 임시 프로젝트 상태를 기록하는 속성은 금지한다.
- 편집 후 커밋·머지 전에 변경 파일의 금지된 섹션 제목, 지나치게 좁은 태그, 중복 속성, 읽기 상태 섹션을 검사한다. Obsidian 원문의 LiveSync 단계는 이 검사 시점으로 대체한다.

기존 노트를 찾고 수정 내용을 반영하는 실행 절차는 [쓰기 흐름](write-flow.md)에 설명한다.

### 민감 정보

도니는 API 키, 비밀번호, 토큰과 같은 비밀값의 저장을 거부하고, 개인정보는 마스킹한다.

### 폴더·태그·위키링크·색인의 역할

- 폴더는 지식 저장소의 큰 구조를 나누는 데 사용한다.
- 태그는 검색·필터링·주제 분류에 사용한다.
- 본문의 위키링크는 큐레이션된 탐색과 직접 참조에 사용한다.
- 색인 노트는 한 영역의 중요한 진입점을 모으는 데 사용한다.

### Frontmatter

- Frontmatter는 최소한으로 유지하며 Obsidian에서 유용한 속성만 둔다.
- 노트의 유지·관리 맥락을 눈에 보이게 남길 필요가 있으면 `updated`를 둔다.
- 운영 규칙이나 검토 기준을 나타내는 노트에는 `importance`를 둔다.
- `importance`의 값은 `high`, `medium`, `low`만 사용한다.
- 폴더와 태그가 이미 같은 정보를 표현하면 `category`, `domain`, `status`와 같은 중복 분류 속성을 추가하지 않는다.
- `belongs_to`, `has`, `related`, `related_to`와 같은 사용자 정의 관계 속성을 추가하지 않는다.

### 태그 정책

- 태그는 `kv-cache`와 같은 영어 소문자로 작성한다.
- 태그는 지식 저장소 전반의 노트를 연결할 수 있도록 일반적이고 재사용 가능한 수준으로 유지한다.
- `v2`, `arxiv-v2`, `guardrail`과 같은 버전·구현 세부 사항·일회성 작업 태그나 임시 프로젝트 상태 라벨을 사용하지 않는다.
- 버전, 실험 단계, 주장 범위, 프로젝트별 결정 맥락은 태그가 아니라 노트 제목이나 본문에 적는다.
- 여러 노트를 발견하는 데 도움이 되면 `papers`, `research-ideas`, `cask`, `kv-cache`, `reasoning`, `inference`, `evaluation`, `llm-agents`와 같은 넓은 주제 태그를 우선한다.
- 새 태그를 추가하기 전에 기존의 더 넓은 태그가 해당 노트를 적합한 주제 묶음에 연결하는지 확인한다.

### 논문 노트의 속성

- 논문 읽기 상태를 frontmatter의 `status`나 `Read Status` 섹션으로 기록하지 않는다. 눈에 보이는 유지·관리 신호로는 `updated`를 사용한다.
- `source`, `pdf`, `arxiv` 속성은 논문 노트에서 정식 외부 식별자를 가리킬 때만 둔다. 이 속성은 분류가 아니라 출처 메타데이터다.
- 프로젝트 방향을 나타내기 위한 버전이나 실험 단계 속성을 추가하지 않는다. 버전과 주장 범위는 제목이나 본문에 적는다.
- 검색·필터링·출처 조회에 유용하지 않은 속성은 추가하지 않는다.

### 사실성과 읽기 맥락

- 노트 본문은 한국어로 작성한다.
- 근거에 없는 내용을 지어내지 않는다.
- 템플릿 안내 문구나 `[이름]`, `<!-- 주석 -->` 같은 placeholder를 남기지 않는다.
- 대화를 그대로 옮기지 않으며, 발언자 이름은 담당자·오너십을 밝힐 때만 사용한다.
- 결론이 나지 않은 논의는 열린 쟁점으로 명시한다.
- 문체는 평서형 종결인 `~다`로 통일한다.
- 6개월 뒤 맥락을 모르는 독자가 읽어도 이해할 수 있게 쓴다.

엔진에는 스레드→문서 고정 템플릿이 없으므로 원문의 H1·메타데이터 생략, 고정 템플릿 섹션, 채택 대안의 `(채택)` 표시, 실행 계획 체크박스, 소급 기록 방식은 채택하지 않는다.
